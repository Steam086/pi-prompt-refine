# 偏好缓存缺陷与连续修订语义实验

## 问题 1：已复现并修复

在同一个工作区内先加载 Unsent 内联库，再经结果的 Revise → Preferences 提交 Add / Edit / Delete，关闭子页后原内联库没有刷新。即使取消子页的**选择**，之前提交的**库写入**也已生效，因此取消路径同样必须刷新。

修复：`src/workspace.ts` 的 Revise Preferences 关闭回调调用已有 `inlinePreferences.refresh()`，与原稿入口一致。不替换已选快照、不自动提交、不改变原稿和 session 守卫。加载期间沿用内联组件已有的隔离逻辑，不把旧库条目当成可新选的当前库。

`test/extension.test.ts` 新增 6 个真实跨入口交互回归：Add / Edit / Delete × Cancel / Bring back。修复前 3 种操作均在返回内联列表时失败；修复后验证新增可见、旧快照来源警告、删除后不再可重选、重新勾选采用编辑后的正文，以及管理/选择不发模型请求、不写宿主编辑器、不发送消息。

## 问题 2：目标风险尚未证实，不删除历史依据

### 实验条件

- 执行日期：2026-11-08（UTC）。
- 生产实现基线：`536e41f` 的 `buildRefineInput()` / `buildRefineSystemPrompt(false)`；本次没有修改它们。
- 真实调用本地已配置的 Pi `ModelRuntime.streamSimple()`，`openai-codex/gpt-6-luna`，reasoning `low`，输出上限 2048，独立无工具请求，不积累聊天消息；没有使用 mock 输出。实验直接使用生产包构造器，未经过完整扩展 UI / controller / 预算适配器，也不代表所有生产配置。
- 仅发送测试文件中的合成任务，没有发送项目内容、会话、偏好库或凭据正文。请求以本地配置认证；模型不执行命令。
- 对比 `current`（现行历史依据）与 `omit-history`（仅从请求包删除整个 `historical_editing_context`，其余协议不变）。这不是对后者优化过的完整新协议。
- 3 个场景：删除初始“Answer in English.”回答要求、保留合法英文翻译、保留合法两项编号格式。后两者防止把“旧要求复活”换成“撤销合法编辑”。

### 两组实验

1. **真实连续链**：每场景/策略 2 次；每链为首次 Refine 加 3 次 Revise，共 12 链、48 次模型调用。删除场景顺序为“删除回答语言要求，不添加任何其他回答语言限制。”→“再精简一点。”→“保留命令原样。”，最后一轮的紧邻指令中已没有删除纠正。后两场景首先仅改善措辞，再精简，再保留命令。
2. **固定候选的晚窗口探针**：每场景/策略 5 次，共 30 次调用。两策略使用完全相同的合成候选，紧邻指令固定为“再精简一点。”，当前指令为“保留命令原样。”。删除场景候选不含任何回答语言要求；另两场景分别仍为英文、仍有两项编号。此组不是完整历史链，用于隔离“旧要求已不在候选且纠正退出窗口”的请求本身。

合计 **78 次真实调用**。42 个测试用例均得到有效 JSON 和正常结束；此处“通过”仅表示请求/输出封装成功，**不是模型语义全部正确**。语义按保存的各轮完整 prompt 人工检查。

### 观察

| 场景 / 指标 | current | omit-history |
| --- | --- | --- |
| 连续链：最后一轮恢复明确的英文回答要求 | 0/2 | 0/1 有效删除链¹ |
| 晚窗口：恢复明确的英文回答要求 | 0/5 | 0/5 |
| 连续链：合法翻译最终保持英文 | 2/2 | 1/2 |
| 晚窗口：合法翻译保持英文 | 5/5 | 5/5 |
| 连续链：合法两项编号最终保留 | 0/2 | 0/2 |
| 晚窗口：合法两项编号保留 | 4/5 | 3/5 |

¹ omit-history 的另一次首次 Refine 已漏掉明确的 `Answer in English.`，不应计入成功删除该要求的样本。两策略的真实链各自生成首次候选，不是配对同一初始输出；固定候选组补足这一控制。

值得区分的具体输出：

- 删除场景的 current 两条连续链最终分别为：
  - `简要说明 \`npm test -- --run\` 的用途和注意事项，不执行命令。`
  - `说明 \`npm test -- --run\` 的用途和注意事项，不执行命令。`
  均未恢复回答语言要求。
- 但 current 晚窗口的 5 次删除探针中，有 1 次把中文候选改成：`Briefly explain the purpose and caveats of \`npm test -- --run\`. Do not execute the command.`。这没有重新写入“用英文回答”，不能算作目标缺陷复现；但当前操作仅要求保留命令，出现了不必要的语言漂移，与旧依据干扰的风险相符，仍需区分原因和扩大样本。
- omit-history 的一条合法翻译链在“再精简一点。”后变为：`简要说明 \`npm test -- --run\` 的用途和注意事项，不执行命令。`，最后一轮保持中文。这是删除全部历史依据可能撤销合法翻译的实际反例。
- 两策略均出现格式丢失。例如 current 一条链从 `1. 解释…\n2. 列出…` 在精简时变成单段，之后未恢复。它说明现行保护并不保证所有先前编辑都被保留，但不是“已删除旧要求复活”。

### 结论与修复方案

**尚未观察到所描述的明确语言要求复活；小样本、单一模型、单一 reasoning 配置不能证明风险不存在。** 不应将原有 mock 测试或本次 JSON 封装测试当成模型遵循协议的证明。

现在保留历史策略，原因是删除全部历史依据已有撤销合法翻译的反例，而且没有改善所有格式保留样本。此次只扩展离线连续修订测试，使明确纠正真正离开紧邻窗口；它只验证字段和冻结来源。

后续方案按风险从小到大：

1. 先对协议做候选优先级的 A/B 实验：原稿用于保留任务/授权边界，当前候选用于判断已生效的语言、格式和要求；历史依据只能解释**仍存在**的编辑，不能据此翻译当前候选或补回已消失的要求。用上述三场景、多模型和多次重复同时评估复活与合法编辑回退，不能只看删除场景。现有协议已有相近文字，新增措辞的效果必须实测，不能假定有效。
2. 若明确复活可稳定复现且协议方案不足，再考虑有界的显式编辑状态（被确认的替换/删除记录），而不是无限累积对话或每轮重放初始要求。不能靠关键字解析任意自然语言来静默撤销已选快照；必须设计来源、确认、预算裁剪、恢复/旧数据兼容与独立测试。
3. 只有对照显示收益后才修改生产历史包。翻译和格式回退可作为独立问题继续实验，不在本次缓存修复中顺带更改语义策略。

### 复跑

默认 `npm test` 跳过真实网络实验。需要本地已配置对应 Pi 模型和认证；以下调用会消耗模型配额：

```sh
REFINE_LIVE=1 \
REFINE_LIVE_OUTPUT=/tmp/revision-chain.jsonl \
npm test -- test/revision-semantics.live.test.ts

REFINE_LIVE=1 REFINE_LIVE_MODE=seeded REFINE_LIVE_REPEATS=5 \
REFINE_LIVE_OUTPUT=/tmp/revision-seeded.jsonl \
npm test -- test/revision-semantics.live.test.ts
```

可用 `REFINE_LIVE_PROVIDER` / `REFINE_LIVE_MODEL` 更换模型。JSONL 追加完整逻辑输入包和最终 prompt，不含认证或隐藏推理；复跑前换输出路径以免混合批次。本次完整逻辑输入包与最终正文已保存为 [连续链原始记录](experiments/revision-semantics-chain.jsonl) 和 [固定候选原始记录](experiments/revision-semantics-seeded.jsonl)；第一批没有 `mode` 字段，均为连续链。完整新批次可用脚本重新生成，输出不保证相同。
