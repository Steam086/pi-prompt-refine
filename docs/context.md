# 上下文与 Prompt 协议

每次优化是独立的 `ctx.modelRegistry.streamSimple()` 调用，不是 Pi Agent session。模型没有跨请求记忆，工具集固定为空；输出通常回到原主会话。实现位于 [context.ts](../src/context.ts)、[project-context.ts](../src/project-context.ts) 与 [extension.ts](../src/extension.ts)。

## Round 快照

每个 round 的第一份输入冻结历史、系统模板、规则/技能资源和上下文配置。之后的不同 prompt、不同模型共享该背景；资源筛选以首份输入为准，不因中途编辑设置而改变。Pi 用户消息开始后自动归档，下一份输入才重新捕获。默认目录树在首次需要时收集并共享；显式目录按 prompt/修订输入冻结。内存中的旧条目运行仍使用旧快照，复制到当前 round 才使用最新背景。磁盘恢复记录不含完整快照，禁止原背景重跑或 Revise，必须显式复制原稿到当前 round。

## 输入来源与选择

| 来源 | 当前处理方式 |
| --- | --- |
| 草稿 | 来自主编辑器、命令正文或 Input 页；完整保留，超过上限拒绝调用 |
| 候选修订 | `operation: revise` 单独传入最初草稿、最新候选与本次修改要求；不把反馈误当新草稿 |
| 会话历史 | `getBranch()` 当前分支中 user/assistant 的可见文本 |
| 项目规则 | 默认关闭；启用后使用 Pi 已加载的 context files，保留来源和宿主顺序 |
| 技能 | 显式启用后提供名称与描述，不读取技能正文 |
| 目录 | 有界名称列表，不读取源码正文；默认 tree 与显式引用分别控制 |

历史不包含 thinking、工具调用块、原始工具结果、图片、其他分支、独立压缩摘要或整套主系统提示。引用普通 `@file` 不代表正文已读取；但用户或助手先前消息中的代码可能随可见历史发送。

### 历史预算

1. 全部可见消息同时满足条数和字符限制时，完整保留。
2. 超限时优先为最新 user 预留约半预算，再保留最新 assistant，其余从新到旧填充；剩余空间回填摘录消息，最后按时间排序。
3. 只有一个名额时选最新可见消息，不能用旧 assistant 替换更新的用户纠正。
4. 长消息仍采用首尾摘录；极小预算可能只保留末尾。这不是语义摘要，不能保证保留所有中段约束。

模型收到逐条 ID、角色及 `complete/excerpted` 状态，还有总条数、入选/省略/摘录计数。整体状态为 `complete/partial/disabled_by_policy`，整条省略也算不完整。完整性仅针对上述可见文本范围。

### 项目规则与技能

命令上下文优先使用 `getSystemPromptOptions()`；普通快捷键从 `getSystemPrompt()` 的 Pi 命名资源区段提取。不兼容或读取失败时告警，不自行扫描全局规则目录，也不发送通用系统规则、认证或技能位置。两种接口的结果不等同于主会话最终 Provider payload。

规则在预算内完整提供，超限时选完整 Markdown 章节并标注来源、行号和不完整状态；不将代码围栏内的标题当章节边界。技能描述整项保留；禁用自动调用的技能只有被原稿以 `/skill:name` 或 `$name` 明确引用时才纳入。技能存在不授权 optimizer 调用它或新增调用要求。

项目规则支持 `First request only`、`Always`、`Off` 三态，默认 `Off`。仅首次以一个优化任务为单位：新草稿的首次优化包含规则，围绕该候选的后续 Revise 省略；主会话是否已有历史不参与判断。规则省略不影响独立启用的技能与目录，也不意味着模型跨请求保留规则。配置映射见 [配置参考](configuration.md)。

### 目录列表

- 默认 tree 开关默认关闭；开启后只在本次实际选中的可见历史为空时收集。原始草稿中的 `@目录` 独立收集，不依赖历史或 `tree.enabled`，但受项目总开关控制。
- 支持相对 cwd、cwd 内绝对路径和带引号的空格路径，如 `@src/`、`@"docs with spaces"`。按字面解释，不展开变量、glob、`~` 或 shell 转义；邮箱、URL 和转义 `\@` 不作为引用。
- 目录限定在 cwd 内，不接受 `..`，逐级拒绝符号链接与 ignored/excluded 路径。默认最多检查 8 个不同引用，每个最多 32 层；普通文件不读取正文。
- 显式引用内部归一化去重，父引用不重复展开子引用。为了跨 prompt 共享默认树，默认树与显式引用独立收集；两者都启用且无历史时，各预留一半字符、条目和扫描预算，并行使用相同超时，合计不因引用数量增加而倍增。默认树与引用可能包含重复路径。只有一个范围启用时可使用完整预算。
- 使用适用的祖先/嵌套 `.gitignore`，不读取 Git 全局 excludes 或 `.git/info/exclude`。默认排除依赖、产物、缓存及 `.env*`，始终排除 `.git`；不执行 shell/Git 命令、不跟随目录符号链接。
- 预算省略、不可访问或不可解析等问题同时进入模型背景与 UI 告警，不触发自动补读。默认深度折叠和正常 ignore 过滤只作列表标注。

宿主资源在 round 捕获时冻结，目录在后台异步收集并共享。取消一个模型请求后不会继续发送该请求，但不会取消其他模型共用的目录准备；目录有自己的有界超时，运行时销毁时统一终止。规则优先于技能及目录；具体默认值见 [配置参考](configuration.md)。

## 发送前统一预算

在字符级采集完成、目录结果及系统模板就绪后，按所选模型的 `contextWindow` / `maxTokens` 校验实际序列化输入、输出预留和安全余量，详见 [预算配置](configuration.md)。模型容量缺失或无效时拒绝调用，不猜测窗口大小。

不足时先缩减多余输出预留，再依次移除可选旧编辑依据（`historical_editing_context`）、目录列表、技能元数据、除最新 user/assistant 外的旧消息、剩余项目背景（可能包括规则）、最新 assistant、最新 user。只移除完整背景项，不再截取消息片段；这是确定性降级，不是语义相关性排序。当前草稿、固定／自定义系统模板、修订原稿、上一候选与修改要求始终不裁剪。完整原稿的输出空间仅为期望值，不是拒绝门槛；背景移除后可继续缩减输出，但仍放不下最低输出空间时停止请求。

实际 JSON 中更新历史完整性与计数，并以 `budget_omissions` 说明新增省略。摘要和运行条目显示 `⚠`，详情列出原因与预算估算。每次模型运行独立预算，保留裁减前的冻结 `preparedInput` 与实际发送的 `sentInput`；较小模型的裁减不污染 round，重试／更大模型可重新使用完整冻结背景。未通过预检时没有 `sentInput`，也不伪造 token Usage。

## 请求与输出

系统消息由固定 refiner 协议、默认或自定义编辑策略、输出与标题要求组成。仅一条 user 消息，其内容为 JSON 数据包，例如：

```json
{
  "operation": "refine",
  "delivery_context": "existing_session",
  "project_context": null,
  "conversation": {
    "scope": "current_branch_visible_user_assistant_text",
    "status": "partial",
    "total_message_count": 2,
    "selected_message_count": 1,
    "omitted_message_count": 1,
    "excerpted_message_count": 0,
    "items": [
      { "id": "m2", "role": "user", "status": "complete", "text": "仅讨论，不实施。" }
    ]
  },
  "draft": "继续看这个方案。"
}
```

ID 优先使用宿主消息 ID，缺失时使用分支位置 `branch-N`。项目背景若启用则为带来源、完整性和告警的文本。JSON 可避免原文中的角色标签或 BEGIN/END 标记改变数据结构，但不能独立保证防御提示词注入。

默认编辑策略要求最小有效修改、允许原样返回，保留字面内容、授权范围与不确定性；助手提议不是已批准需求，指代只在依据充分且唯一时消解。模板位于 `context.ts`，不加载 `.pi/prompts/*.md`，也不展开草稿里的 `/模板名`。

Preferences 库 JSON 在插件侧解析和校验；本次手动选择的正文按类型和手动来源标注后进入 `editing_instruction` 或 `revision_instruction`，相同类型／正文只注入一次。`composeRevision` 将有元数据条目的 `kind` 转为 `Prompt rewriting instructions`（改变 prompt 表达）和 `Main-agent task requirements`（补充主 Agent 的回答／行为要求）文本标签，不发送 JSON `kind` 字段；旧条目为 `Saved editing requirements`。组合自由输入独立标为 `Current user instructions`。名称、描述、ID、版本、匹配配置和完整库不进入模型请求。所有偏好均需用户手动选择，没有本地关键词自动匹配或自动采用；旧库自动项兼容读取为手动项，详见 [元数据与旧库兼容](usage.md#json-元数据与手动选择)。协议允许明确翻译 prompt，区分回答语言与 prompt 语言，要求当前明确任务／修订纠正优先于冲突默认项，禁止模板扩大执行和委派授权。初始选择不在 Revise 中机械重放，避免恢复已被明确删除的要求。

`Main-agent task requirements` 是用户选择的补充要求，不是替代任务，也不只是给 refiner 的过程指令。输入时原稿与要求保持独立；固定协议要求把适用且兼容的内容融入最终 prompt 正文，返回含原任务和整合要求的完整 prompt，而非只返回补充要求。保留原任务、适用的明确约束、条件和授权边界，合并重复内容，去掉面向 refiner 的包装措辞；refiner 自身不执行要求。仅选择偏好不覆盖原稿明确约束，也不增加执行、工具或委派权限；只有当前用户明确要求的修改才能改变已有要求，仍允许明确翻译或缩小任务范围。这是协议约定，单元测试检查协议文本与请求构造，不证明模型必然遵守。

Revise 的可选 `historical_editing_context` 保存初次手动采用的编辑要求与紧邻上次修订要求，仅解释 `previous_candidate` 中仍存在的改动（例如翻译）。它不是待重新执行的指令，当前修订纠正优先，候选已删除的要求不得恢复；不查询当前库，也不累积完整修订链。没有选项快照的旧输入仅能保留原组合文字作历史依据。该字段参与完整预算，紧张时在具体背景之前整项省略并告警；不随最小 sidecar 新增持久化字段。协议约定不等于模型遵循保证；纠正退出紧邻窗口后的有限真实模型对照及风险见 [连续修订语义实验](revision-semantics-experiment.md)。

响应为 `{"prompt":"…","title":"…"}`，已命名时仅需 `prompt`。非法 JSON、空 prompt、截断和工具调用均拒绝，不回退到原始响应；无效可选标题只跳过命名。同 round、同原稿、模型、thinking 和修订输入的在途请求去重；裁减前 JSON 输入（含异步目录结果）和实际发送输入分别写入运行记录，重复运行复用完整来源并重新按目标模型预算。

## 数据与能力边界

所选优化 Provider 会收到草稿和启用的背景，可能不同于主 Agent Provider；不能自动识别文本中的全部秘密。过程不写入主会话对话；默认在相邻 sidecar 保存有界的原稿、结果、已提交修订要求与运行元数据，不保存完整背景或请求载荷。原稿和结果仍可能含敏感信息，可用 `historyPersistence: false` 关闭保存，或 `/refine history clear` 删除当前 session 的保存记录。模型只能返回改写，不能读取文件、联网或执行任务。

候选修订复用来源请求的冻结背景和规则策略；First 模式的修订规则快照也在 round 首次捕获时准备。修改要求中的显式目录引用同样受目录规则限制。原始草稿和本次修改要求分别受 `maxDraftChars` 限制，上一候选受输出字符上限限制；不向模型无限累积修订链。修订失败保留来源候选，切换模型不取消其他运行，会话/分支切换则终止在途请求。

当前不提供模型评分、`need_context` 或渐进式补读。统一预算已提供近似容量预检；精确 Provider token 核算、相关性选择与真实模型语义效果验证仍属后续方向，见 [设计原则与演进方向](../DESIGN.md)。
