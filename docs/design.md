# 设计原则与演进方向

Pi Prompt Refine 在后台结合当前对话整理草稿，由用户审阅后决定是否接受或发送。模块与状态归属见[维护架构](architecture.md)，近期工作见[路线图](roadmap.md)。

## 现行设计

- **由用户控制副作用。** 生成、接受和发送是独立动作。Apply 只切换 Refine 当前结果，接受只回填编辑器，发送需要明确操作。后台完成保留焦点、阅读位置与动作目标，关窗或断线后运行继续。覆盖已变化的草稿前须确认，确认后重新校验会话、候选和编辑器。见[使用说明](usage.md)及[界面维护约束](ui-conventions.md)。
- **隔离改写请求。** 每次运行复用 Pi 的模型注册表与认证，按 Refine 的独立配置发起一次无工具改写。改写中间过程留在 Refine。TUI、`/refine-api` 和 Web 复用应用用例，客户端状态共享限于同一个 hosted session runtime。会话或分支切换、runtime 销毁会使旧操作失效。见[多入口应用接口](application-api.md)及[请求与会话验收约束](testing.md#请求与会话)。
- **冻结上下文与比较输入。** round 的首份输入冻结系统模板、历史及项目资源，同轮草稿共享这份背景。同一原稿的模型比较从共同输入开始，显式修订使用原稿、当前候选和本次要求。只在 Pi 用户消息的 `message_start` 归档当前 round，后台运行可以继续。见[上下文与 Prompt 协议](context.md)。
- **保留原意与授权。** 草稿定义目标，历史与项目资源帮助澄清指代和约束。保留用户已确认的约束，准确表达建议与假设的确定程度。改写应整理有歧义或松散的表达，清楚的原稿可以原样返回。路径、代码、命令、TUI 和引用等字面材料默认保留，编辑须有明确授权。固定角色与输出协议独立于可编辑策略。见[默认改写策略](../AGENTS.md#默认改写策略)。
- **显式选择偏好。** 用户逐次选择或设为项目默认，保存和选择本身不发起请求。`rewrite` 指导如何改写，`task` 补充主 Agent 的任务要求。已选条目以快照进入请求，库变化不覆盖旧选择。见 [Preferences 选择与保存](preference-selection.md)。
- **限制历史保存范围。** sidecar 保存原稿、结果、已提交的编辑要求和运行元数据。完整背景与请求载荷留在运行期。要用恢复的原稿再次请求，须显式复制到当前 round。保存范围、容量和清理方式见[配置参考](configuration.md#历史保存与隐私)，用量及参考费用见[使用说明](usage.md#用量与参考费用)。

## 验证边界

离线检查覆盖协议、预算、竞态和界面行为。实体终端交互及中文 IME 需要人工验收。见[测试与重构验收](testing.md)。

用真实模型做语义对照，以未改写的原稿为基线，检查指代、硬约束、字面材料、授权范围和连续修订的漂移，同时记录延迟与用量。见[语义验收样例](optimizer-evaluation.md)和[连续修订实验](revision-semantics-experiment.md)。

## 演进方向

以下方向仍需验证和讨论，实施范围与排期待定。

### 上下文选择与预算

当前按各模型的窗口和输出能力做近似预检，预算不足时按固定顺序省略完整背景项，保留完整草稿。见[发送前统一预算](context.md#发送前统一预算)。

- 先验证单次请求内的确定性选择与更精确的 Provider token 估算。仅从用户允许的来源选择完整语义片段，为仍适用的约束、近期纠正和指代依据保留预算。比较语义保真、整次延迟及累计用量。
- 探索在 round 内冻结来源快照、按草稿选择背景。同一原稿的模型比较与重试保留选择依据，各模型仍按自己的预算取舍。提交前可考虑展示选中、排除和超预算省略的来源，并允许针对本稿调整。
- 在关键背景仍缺失时，再评估有限的渐进补读。相关性随改写目标变化，模型评分与额外调用都计入延迟和用量。补读沿用同一次请求的授权、预算、取消和失效边界。见[上下文补充草案](progressive-context-fallback-plan.md)。

### 偏好与策略

已取消关键词驱动的自动匹配。问句、顺序词等线索难以区分引用中的要求与用户本次指令，额外分类也会增加维护或请求成本。

- 先用现有 Preferences 和 Revise 验证长短、结构偏好、高频复用与连续修订。根据真实使用中的操作成本和语义保真，再评估多套优化策略、首次改写的单次自由输入或模板版本管理。
- 如需评估偏好推荐，先用基础策略、手动选择和历史关键词方案做对照，检查约束丢失、授权变化和纠正次数。任何推荐仍由用户显式选用，接受或发送仅提供有限的行为信号。

### 历史分析与请求复现

- 先明确跨会话用量汇总、导出和反复修订分析需要哪些字段，以及它们的保留期限。接受、发送和未选择只作为行为记录，评价原因需独立证据。
- 复现研究可先记录策略、模板与偏好版本、来源摘要及预算诊断。完整输入快照需要单独选择保存范围，明确保留、清理和导出边界。
