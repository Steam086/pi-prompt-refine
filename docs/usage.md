# 使用说明

安装与最小流程见 [README](../README.md)。以下补充交互细节；配置字段见 [配置参考](configuration.md)。

## 触发、查看与重新优化

默认全局入口为 `Ctrl+\`（Control + 反斜杠，不是 Command）。

| 当前状态 | 入口行为 |
| --- | --- |
| 没有工作流记录，已选模型且草稿非空 | 启动后台优化 |
| 生成中、结果就绪或等待发送确认 | 打开当前面板，不重复调用模型 |
| 已接受结果，即使编辑器随后已修改 | 查看已接受的只读快照 |
| 上次失败 | 查看错误，明确按 `r` 才重试 |
| 未选模型或草稿为空 | 打开操作面板 |

关闭面板不取消后台任务；完成时只更新摘要，不自动弹窗。面板 `r` 明确重新优化当前主编辑器，原稿、候选或已接受记录不会被隐式当成新的输入。新输入无效时保留旧结果；相同在途请求仍去重。

### 命令备用入口

```text
/refine 待优化文本
/refine optimize 待优化文本
/refine view
/refine model
/refine cancel
/refine cycle
/refine restore
```

`/refine` 不带参数也打开面板。正文保留大小写与内部空白，支持多行；若正文恰好是 `view` 等子命令，使用 `/refine optimize view`。

无参数 `/refine optimize` 读取当前编辑器，但 Pi 提交 slash command 时可能已清空编辑器，因此命令入口推荐显式携带正文。扩展会把命令原稿留回空编辑器，不覆盖已有的其他草稿，也不直接发送给主 Agent。

## 面板操作

以下字母键只在 Main 页生效；普通 Enter 不发送候选。完成态底栏突出 `a Accept`、`e Edit`、`f Revise`，另保留 `q Back` 和 `? Help`；其余按键仍有效，完整说明在 Help 中。正文弱化说明 Accept 只放入编辑器、`s` 直接发送，顶部 `→ Settings` 提示设置入口。生成中突出 `x Stop`；已接受快照不显示候选操作，发送待确认时不再提示接受、编辑、修订或再次发送。

| 按键 | 操作 |
| --- | --- |
| `a` / `e` / `s` | 接受到主编辑器 / 独立微调候选 / 明确发送 |
| `f` | 输入修改要求，再次调用模型修订当前候选 |
| `x`（兼容 `d`）/ `z` | 取消任务并丢弃候选 / 恢复上次接受前的草稿 |
| `r` / `m` / `c` | 重新优化当前草稿 / 选择优化模型 / 循环收藏模型 |
| `o` / `v` / `?` | 展开原稿 / 切换 Markdown 与纯文本 / 展开帮助 |
| ↑↓ / Page Up / Page Down | 滚动正文 |
| `i` / `→` | 进入 Input / Settings 页 |
| `q` / Esc / `Ctrl+\` | 返回主编辑器，保留候选和后台任务 |

- **Input**：输入的是新草稿，不是对上一候选的反馈。Enter 提交优化，Shift+Enter 或 Ctrl+J 换行，Esc 返回；提交不改主编辑器、不发送。未提交文本只在本次工作区内保留。
- **Revise（`f`）**：只对当前未接受、未发送的候选开放。输入修改要求，Enter 发起一次修订，Esc 返回不调用模型；输入与 Input 页独立。请求携带最初草稿、最新候选、本次要求，不无限累积优化对话。成功后替换候选；失败、无效输出或超时保留之前候选，可再次按 `f`。候选或会话在输入期间变化则拒绝旧操作；重新进入时新候选不会沿用旧反馈。接受/发送仍须明确操作。
- **Settings / Context**：↑↓选择，Enter / Space 操作当前项；`Project instructions` 在 `First request only`（每个新任务首次包含，Revise 省略）、`Always`（每次包含，默认）、`Off`（始终关闭）之间循环，目录树与技能仍为复选项。修改仅暂存，任意行按 `Ctrl+S` 保存 Context 并返回；设置对后续请求持续生效，不改变已有结果或正在执行的请求。`←` / `q` / Esc / `Ctrl+\` 返回，只放弃未保存的 Context 修改。默认包含目录树，不包含技能元数据。
- **Settings / Optimizer**：模型选择确认、thinking 切换、编辑策略独立确认后立即生效并尝试持久化，不受 Context 保存或取消影响，主会话不变。没有可用模型或模型的 thinking 等级固定时，该行显示禁用原因且不能切换。选项说明与长值放在固定详情区，↑↓只在选中项越过可见区域时滚动。
- **阅读**：摘要最多 6 行正文；完整面板限宽、内部滚动，支持原稿和帮助展开。展示转换不改变接受或发送的文字。用量只显示响应提供的计数，不估算缺失值。

## 接受、发送与恢复

接受会写入编辑器但不发送；独立微调只改候选。编辑器草稿已变时，接受或恢复需要覆盖确认，确认返回后再次检查文本与会话。

直接发送只发送当前候选，保留编辑器中的草稿；主 Agent 忙时以 `followUp` 排队，不默认打断。请勿因原稿仍在输入框而误重复提交。Pi 接收/排队确认不代表模型已处理完成。

接受后再修改编辑器，入口只展示旧的只读快照，`a/e/s` 禁用；若要优化当前修改稿，明确按 `r`。这些来源和恢复记录只在内存中，提交消息、会话/分支切换、reload 或退出后清除。

## 会话名称

未命名会话可在同一次优化中返回候选名称，预览单独展示，不混入 prompt。只有成功接受或 Pi 确认发送/排队后才应用名称；等待期间已有的手动命名不覆盖。无效可选名称不影响有效 prompt，恢复草稿不撤销名称。

命名由 Pi 元数据持久化；曾经命名后即使主动清空，也不会再次自动命名。

## 模型、兼容性与排查

首次安装/加载时若尚未配置优化模型，扩展提示 `/refine model`，不自动选择主模型，也不自动请求或下载模型。取消选择不写配置；没有可用模型时先在 Pi 配置 Provider 和认证。首次选择成功后提示开始方式；若配置保存失败，会明确说明仅当前进程生效。

`/refine model` 展示 Pi 已授权的 chat 模型，可搜索 provider、名称或 thinking 能力；不受主会话 scoped-models 列表限制。默认 Shift+Tab 循环所选模型支持的思考强度；未设置扩展覆盖时继承当前 session，宿主未提供则使用 `medium`，再按模型能力调整。不会改变主会话模型或 thinking。

`Ctrl+\` 已在 Pi 1.4.0 键解析器中验证，但终端、键盘布局和其他扩展仍可能拦截。用 `/hotkeys` 检查当前绑定，或使用显式文本命令。不要在普通 Shell 提示符测试该键，它可能触发 SIGQUIT。更多见 [快捷键排查](shortcut-troubleshooting.md)。

本扩展只处理可获取的文本，不承诺保留附件、光标或选区。真实终端观感、IME 和真实 Provider 效果尚需验收；UI 取舍见 [TUI 说明](ui-refinement.md)。
