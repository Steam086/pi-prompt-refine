# 使用说明

安装与首轮操作见[中文 README](../README.zh-CN.md)。下文按原生 Pi 工作台说明操作，T3 Code 用户可直接查看 [RPC 用法](#在-t3-code-中查看结果)。

## 快捷键：每轮首次直接优化

选好优化模型后，在 Pi 输入框输入新草稿，按 `Ctrl+\`。本轮首次请求通过校验后直接启动，并采用会话选择及其继承的项目默认 Preferences。同一轮后来捕获的新草稿显示为 **Unsent**，需要选中并按 Enter 才启动。想在第一次请求前挑选偏好，可先用 `/refine` → `p` 为本会话设置，也可用 `/refine` → `n` 创建原稿后单独选择。空输入或未配置模型时快捷键只打开工作台，已有相同输入时定位原记录。若项目默认组合超长，可在 Unsent 中减少选择后再运行。每次改写可能消耗优化模型额度。

## Round：发送后自动归档

一个 round 共享首次捕获时的[冻结背景](context.md#round-快照)。运行入队即算本轮已经请求过，失败、取消或删除不会重置。Pi 开始处理新的用户消息才结束当前轮次，接受结果回编辑器不会结束它。旧任务可在 **Usage** 继续查看和停止，原有后台运行也会完成。

## 工作台与统一 Usage

左右键切换 **Preview**（当前轮次）、**Usage**（含历史）和 **Settings**。任务树父节点是原稿，子节点是各次运行。上下键选择，`?` 查看当前可用的完整操作和反馈。在顶层标签按 `Esc` 关闭工作台，Settings 有暂存改动时先确认是否放弃。在记录详情等子页面，`Esc` 返回上一级。

| 操作 | 入口 |
| --- | --- |
| 新建或编辑原稿 | `n` 新建，`i` 编辑。Enter 保存，Shift+Enter 或 Ctrl+J 换行。编辑已运行或已归档原稿会创建当前轮次副本。 |
| 运行或查看 | Unsent 按 Enter 启动，其他条目按 Enter 查看详情。 |
| 停止 | 选中排队或运行中的子节点按 `x`。关闭工作台后任务仍可继续。 |
| 接受结果 | 选中有结果的运行按 `a`，回到 Pi 编辑器审阅。 |
| 比较或修订 | 详情按 `c` 比较同原稿的候选，按 `f` 进入 Revise。 |
| 查看用量或存储 | 在 Usage 中打开记录；按 `b` 查看旁车文件路径和保存状态。 |

### 浮窗与长文阅读

原生浮窗随终端尺寸分配空间，切页、子页和异步完成使用同一个框。短窗口可能遮住 Pi 底栏的一部分。详情用 `o` 聚焦或切换结果与参考，方向键或翻页键滚动。两者保留各自位置，接受、编辑和修订仍针对选中的运行。Compare 用 Tab 切换目标，接受前检查标题中的运行编号。

### 并行优化与对比

在原稿或其运行上按 `m` 选择模型，Enter 提交一次比较。比较使用共同原稿和背景，不会把选中候选当新草稿，也不会改变默认优化模型。达到并发上限后按提交顺序排队，超时从实际启动开始计。可单独取消每个运行。

## 兼容结果页：接受与发送各自独立

`/refine view` 查看当前已应用候选。**Apply** 只切换 Refine 中的候选，`a` 回填 Pi 编辑器，`s` 明确发送。首次直接发送会提示主模型额度；Pi 忙时可排为 follow-up，原编辑器草稿保留。接受或恢复若会覆盖后来编辑的草稿，须确认。发送等待宿主回执时显示 `Send pending`，超时后先查 Pi 队列再重试。

结果详情可按 `e` 保存独立手工版本。兼容页的 `r` 明确优化当前 Pi 草稿，`g` 以该任务冻结的输入追加运行，`z` 恢复接受前被替换的草稿。其余兼容操作见页内 `?`。

## Input、Revise 与 Settings

- **Input**：兼容结果页按 `i` 打开独立输入。空工作区中 Enter 启动优化，已有内容时保存为 Unsent。主工作台用 `n`／`i` 编辑原稿。
- **Revise**：从有可用背景的结果按 `f`，输入针对候选的修改要求。Enter 换行，Ctrl+S 提交，Esc 返回。布局允许时 Ctrl+E 切换仅编辑／显示来源。失败保留来源结果。修改要求可以结合[偏好库](preference-selection.md#完整面板all-与-selected-only)，从库返回后再提交。
- **Settings**：操作和生效范围见[配置参考](configuration.md#settings-面板)。

## 保存与复用编辑要求（Preferences）

在 Preview 按 `p`。高亮可编辑 Unsent 时只修改该原稿，否则修改本会话后续新 prompt 的选择。`Space` 即时保存勾选，`g` 单独设项目默认，Esc 只返回。在 **Library** 列表用 `n`、`e`、`d` 管理库条目，已捕获的快照会保留。在 Usage 的运行上按 `p` 打开只读审计。返回 Unsent 按 Enter，或返回 Revise 按 Ctrl+S，才会提交请求。[项目默认与选择详情](preference-selection.md)

**In Your Own Words** 可显示模型对原稿的理解。可在 Preferences 中选择该内置项，或通过 **Add** 创建自定义附注。[Result notes 使用方式](preference-selection.md#result-notes)

### JSON 元数据与手动选择

可编辑的库格式参见[随包示例](../examples/prompt-refine-preferences.json)，旧库兼容与默认初始化见[库文件说明](preference-selection.md#库文件与旧版兼容)。

## 记录范围与用量

运行记录按 Pi 会话保存或查看。在 **Usage** 中按 `b` 检查哪些运行已保存、哪些只在内存中。要关闭保存或删除当前会话的历史文件，见[历史保存与隐私](configuration.md#历史保存与隐私)。

### 用量与参考费用

总输入含未缓存输入及缓存读写，部分统计缺失时不会推算完整数值。Reasoning 已计入输出。费用来自该次响应的 SDK 参考值，`Cost —` 表示未知，`(sub)` 表示订阅认证下的参考价。以 Provider 的账单和实际额度为准。手工编辑不产生模型用量。

### `/resume` / `/reload` 后的历史

历史以归档记录恢复。未完成的运行标为 `Interrupted`，旧队列和编辑器状态不会恢复。缺少冻结背景的记录可查看或显式使用已保存的结果。要再次优化原稿，用 `i Copy to current` 复制到当前 round，保存后再运行。保存失败、文件路径和仅内存记录都可在 Usage 的 Storage 页检查。

Pi 报告可识别的网络传输故障时，Usage 显示 `Error: network`。历史保存分类码，恢复会话后仍可查看。

## 命令备用入口

```text
/refine model
/refine optimize 解释刚才的第二个方案，先别改代码。
/refine view
```

命令正文是显式请求，不受首次快捷键规则限制。原稿与子命令同名时用显式形式，例如 `/refine optimize model`。`/refine usage`（兼容 `/refine history`）打开用量页。独立的 `/refine-api` 语法、结果查询与重试见[应用接口](application-api.md#refine-api)。

### 快捷键无响应

先用 `/refine` 打开工作台，或用 `/refine optimize <文本>` 继续改写。在出现问题的 Pi 会话中运行 `/hotkeys`，确认绑定已加载，再回到主编辑器试按。如果只在终端复用器中失效，用同一个 Pi 配置在直接终端复测。`Ctrl+\` 在普通 shell 提示符下可能触发 SIGQUIT，请在 Pi 编辑器内测试。

### 在 T3 Code 中查看结果

先在使用同一 Pi agent 目录的原生 TUI 执行 `/refine model` 选好模型，再回到 T3 Code 线程提交 `/refine optimize <文本>`。结果就绪且 Pi 空闲、当前对话框关闭后，原线程会弹出预填候选正文的 **Question**。可全选复制，按 **Submit** 关闭并回到先前的草稿。预览中的编辑会被丢弃。要重看，复制回执或状态中完整的 `/refine result …` 命令。重看不会再次调用模型。切换 Pi 会话或分支、重载扩展后，原命令会失效。[宿主版本与实测范围](rpc-slash-verification.md)

## 会话名称与兼容性

未命名会话可随改写得到可选标题。接受或确认发送才可能设置会话名称，已有名称优先，恢复原稿不撤销标题。改写面向文本草稿。Pi 管理模型可用性和认证，Refine 的选择独立于主模型。
