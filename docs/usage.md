# 使用说明

安装与最小流程见 [README](../README.md)，配置字段见 [配置参考](configuration.md)。本扩展是无工具的后台改写器，不执行 prompt 中的任务。

## 快捷键：打开与捕获，不覆盖

默认入口是 `Ctrl+\`（Control + 反斜杠，不是 Command）。

| 当前情况 | 行为 |
| --- | --- |
| 工作区确实为空，已选模型，Pi 输入框非空 | 捕获输入并自动启动第一次 refine |
| 已有任务或保留结果，输入变成新的非空文本 | 追加 `○ Unsent` 条目，打开工作台；**不自动请求** |
| 输入没有变化、已经捕获或为空 | 只打开工作台，不重复入列或调用模型 |
| 没有配置模型 | 打开面板，先用 `m` 或 `/refine model` 选择 |

生成中也使用相同规则。新输入不会取消或替换已有请求，不会清空 Pi 输入框。比较保留空白与换行，不做语义去重。旧 round 归档后仍有保留内容，不算空工作区；未变化的旧输入不会因为归档而重复捕获。

关闭工作台不会停止任务，完成也不会自动弹窗或移动列表选择。超长输入或不可用模型会提示，已有内容保留。

## Round：发送后自动归档

一个 round 包含一份冻结上下文、多份 prompt，以及各 prompt 的模型运行和结果。

1. 第一份输入捕获时冻结可见历史、系统模板、项目资源及上下文配置。
2. 同 round 的新 prompt 共享这份背景；追加模型运行、查看详情、接受到编辑器、修改配置均不切 round。
3. **Pi 发出用户消息 `message_start` 后**，当前 round 自动归档。适用于 Pi 输入框直接提交和扩展明确发送；原始 `input`、`before_agent_start` 可能仍被拦截或失败，不作为成功发送依据。
4. 下一份新输入捕获时，才获取最新可用上下文并创建新 round。没有手动刷新操作，也不承诺包含尚未生成的 Pi 回复。

归档不是取消：旧请求继续运行，结果归属旧 round；旧的未发送条目仍绑定原快照。列表默认显示所有保留轮次，当前轮次在上，旧轮次在下并变灰。右侧明确提示 `Uses earlier conversation context`，正文保持正常阅读颜色。编辑旧原稿会创建当前 round 的副本；直接运行旧条目仍使用旧背景。

默认目录树在 round 首次需要时收集并共享；显式 `@directory` 按 prompt（含修订要求）收集并冻结。相同输入的并行模型运行共享收集结果，一条请求取消不取消另一条的上下文准备。规则和技能来自捕获时的 Pi 资源，不读取源码或技能正文。

## 工作台与统一 Usage

顶层页面为 **Preview / Usage / Settings**，不再有独立 History 页。`/refine history` 保留为 Usage 的兼容别名。

宽屏采用左侧「原稿 → 各次模型运行」两层树、右侧正文；窄屏通过 Tab 切换列表与阅读。父节点可选中，Unsent 是没有运行子节点的原稿。子节点代表一次运行，同一模型重试也保留独立记录。当前轮次优先，各轮次内按最新任务组排序，组内最新运行在上；新增运行使该组前移，完成不会重新排序或移动选择。

| 列表操作 | 行为 |
| --- | --- |
| ↑↓ / Page Up / Page Down | 选择父节点或运行子节点 |
| Tab | 切换选择／阅读焦点；阅读时方向键滚动正文，各条目保留滚动位置 |
| Enter：Unsent 父节点 | 使用默认优化模型启动；空白不能启动，旧条目仍使用旧背景 |
| Enter：其他条目 | 查看原稿或运行详情，包括排队、运行、失败和取消；不 Apply、不写 Pi、不发送 |
| `n` | 顶部新增空白原稿并进入编辑；无需先配置模型 |
| `i` / `e` | 编辑选中条目所属原稿；当前 Unsent 原地修改，已运行或旧轮次创建当前轮次副本 |
| `m` | 选择模型，Enter 直接为该原稿启动一次运行；不更改默认模型 |
| `x` | 只停止选中的排队／运行子节点；父节点不批量停止，完成记录保留 |
| `a` | 将选中运行的结果写入 Pi 输入框，不发送；父节点不自动挑选模型结果 |
| ← / → | 循环切换 Preview / Usage / Settings |
| Esc / `q` | 返回／关闭；关闭不取消后台任务 |

原稿编辑器中 Enter 只保存，Shift+Enter / Ctrl+J 换行，Esc 取消本次编辑；取消新建或复制会移除临时草稿。保存后返回列表，再按 Enter 才请求模型。编辑期间原稿启动或会话换轮会拒绝旧保存，避免修改已经提交的输入。显式新建允许相同文本，快捷键自动捕获仍保持去重。

右侧顶部只显示模型／状态、Provider 与 Thinking、加粗耗时及已报告的总 Token。运行中耗时使用强调色，每秒更新；排队不计入运行耗时。顶部固定，正文单独滚动。旧背景、错误和上下文警告保持可见，Branch 标识和 Frozen context 术语不出现在普通界面。

Enter 详情内保留 `e` 编辑结果、`f` 修订、`s` 发送、`o` 原稿对照与 `g` 默认模型重试；这些高级操作不占用主界面的主要提示。Usage 是实时视图，完整用量和记录信息在正文后，方向键滚动查看。手工编辑标注 `Manual edit · no model call`，不当作模型调用。

### 并行优化与对比

选中原稿或模型子节点，按 **m → Enter** 使用另一个模型运行。选择器支持搜索，最近使用和收藏的其他模型优先，显示当前任务下各模型的 Running / Queued / Done / Failed 状态。Thinking 初始沿用选中运行的配置并按目标模型能力调整，选择器中可修改，只作用于本次请求。

- 所有比较运行使用共同的 original prompt、系统模板和会话背景；从修订或手工编辑结果上按 m 也不会把输出当成新输入。
- 默认模型／thinking 通过 Settings 或 `/refine model` 修改；一次对比不持久化这些设置。
- 相同模型与 thinking 已在该原稿下运行时，定位已有请求；完成后可以再次运行，保留之前的输出。
- 最多同时运行 **4** 个请求，超出后按提交顺序排队；顶部置新仅影响展示。超时从实际启动时计算。
- 每次运行独立取消、超时、失败；失败不自动重试、不自动切换 Provider。
- 正等待 Pi 发送确认时，暂停结果操作和模型选择，避免投递目标改变。

主界面上下选择同级模型即可快速阅读比较。Enter 结果详情后按 `c` 与同原稿的另一份结果对比，再按 c 切换比较对象，遍历后退出比较。宽屏并排显示，左侧是当前选中结果；Tab 交换当前选择，`a` 接受标题明确标出的模型／运行。窄屏显示当前结果，Tab 在两份结果间切换。比较只阅读，不会发起调用。

## 兼容结果页：接受与发送各自独立

`/refine view` 直接查看当前已应用结果；快捷键和无参数 `/refine` 打开工作台。结果页可以继续阅读原稿和 Markdown／源码视图。

| 按键 | 操作 |
| --- | --- |
| `a` | 接受到 Pi 输入框，**不发送** |
| `e` | 手工微调并保存新版本，不调用模型；保留原结果 |
| `f` | 输入修订要求，携带最初原稿、当前结果、本次要求调用模型 |
| `s` | 明确发送给 Pi；忙时使用 `followUp`，保留输入框草稿 |
| `g` | 使用该任务冻结输入后台追加运行并返回任务列表；完成后在列表查看，不替换当前结果 |
| `r` | 明确读取 Pi 当前草稿并发起 refine，仍使用当前 round 的上下文 |
| `[` / `]` | 切换当前展示模型的候选 |
| `o` / `v` / `?` | 原稿对照／Markdown 与纯文本／帮助 |
| ↑↓ / Page Up / Page Down | 滚动正文 |
| `z` | 恢复上次接受前实际被替换的 Pi 草稿 |
| `x`（兼容 `d`） | 停止当前预览请求或取消预览，不删除日志或停止其他任务 |
| `q` / Esc | 从列表进入的结果页返回工作台；直接 view 的结果页关闭返回 Pi |
| `Ctrl+\` | 关闭工作区，不接受或发送 |

接受／恢复若会覆盖后来修改的 Pi 草稿，需要确认；确认返回后重新检查草稿、候选 token 和 session。Apply 没有 Pi 编辑器副作用，因而不要求覆盖确认。手工编辑保存为独立版本，不会被其他请求完成覆盖。

兼容结果页中的已接受快照只读。可以在任务树／Usage 中选中历史结果，显式接受、编辑或修订；这些操作不把旧 round 恢复为当前 round。希望使用当前背景再优化旧原稿时按 `i` 复制编辑。

发送待确认不等于模型处理完成。排队消息只有开始成为 Pi 用户消息后才归档；发送失败不切 round。发送超时只表示扩展未等到确认，不证明 Pi 队列中没有该消息，请检查队列后再重试，避免重复发送。普通 Pi 提交只归档 round，不猜测它对应哪条候选的明确发送事件。

## Input、Revise 与 Settings

- **原稿编辑**：主界面 n / i / e 使用选中任务绑定的编辑器，保存不调用模型。
- **兼容 Input**：`/refine view` 的 i 仍保留独立输入稿，Enter 在空工作区启动优化，已有内容时只追加未发送条目；Shift+Enter / Ctrl+J 换行。提交不写 Pi 输入框。按 session 保存运行期草稿，提交、关窗、切模型和后台完成都不清空；主动清空也被记住。
- **Revise**：只修订当前可操作结果，不把反馈误当作新原稿。Enter 明确请求；成功追加结果，失败／超时保留来源候选。输入绑定候选 token，目标变化后拒绝旧操作。修订使用来源的冻结上下文和规则策略，不采纳中途修改的 Context。
- **Settings**：Context / Optimizer 两组，Tab 或左右键切组；外侧边界左右键切顶层页。↑↓选择，Enter / Space 更改项目，Ctrl+S 保存 Context。切页保留暂存设置；在 Settings 取消或关闭工作区时放弃未保存 Context。
- **Context 设置**：规则 `First request only` / `Always` / `Off`、默认目录树和技能元数据。规则 First 模式对修订省略规则，策略在 round 捕获时冻结。配置修改用于**下一 round**，不偷偷改变当前任务。
- **Optimizer 设置**：模型与 thinking 选择用于下一次显式启动，不改变主 Agent。系统编辑策略变更同样要等下一 round 捕获。配置持久化失败会明确提示仅进程内有效。

## 记录范围与用量

日志仅在扩展运行期内存中，按 Pi session ID 隔离，不按项目聚合，不自动进入模型上下文。Usage 可跨当前 session 各分支查看本次加载后的记录，不能恢复以前运行期的记录。

整个日志最多 **100 条**（不是每个页面或每个 session 各 100 条）。容量满时优先淘汰最早的已终结记录；未发送、排队和运行中记录不会被静默淘汰。全部被待处理工作占满时拒绝新增并提示，Pi 草稿仍保留。reload、退出及宿主重建扩展运行时后清除。

详情包含原稿、结果、模型与 thinking、round／任务／父记录、错误、接受／发送标记、耗时和实际返回的 Token：total、input、output、cacheRead、cacheWrite、reasoning。缺失不估算，明确返回零才显示零；没有总费用或跨请求汇总。取消后迟到的用量可以入账，但不会复活候选。

## 命令备用入口

```text
/refine
/refine 待优化文本
/refine optimize 待优化文本
/refine view
/refine usage
/refine model
/refine cancel
/refine cycle
/refine restore
```

显式正文命令与 `r` 是明确发起请求，不受快捷键“只入列”规则限制，但不会取消其他请求。正文保留大小写与内部空白；与子命令同名时使用 `/refine optimize view`。Pi 可能在 slash command 提交时清空输入框；扩展只在空输入框中保留命令原稿，不覆盖其他草稿。

## 会话名称与兼容性

未命名会话可在同一次模型调用返回可选名称，预览单独展示，不混入 prompt。只有接受到编辑器或确认发送后才设置名称；Apply 不命名，不覆盖后来出现的手动名称。无效名称不影响有效 prompt；恢复草稿不撤销名称。曾经命名后，即使主动清空也不再次自动命名。

模型列表来自 Pi 已授权的 chat 模型；不借用或切换主模型，也不下载模型。默认 Shift+Tab 切换所选模型支持的 thinking；没有扩展覆盖时继承 session，缺失则使用 medium，再按模型能力调整。

仅支持 TUI 文本，不承诺保留附件、光标或选区。`Ctrl+\` 的终端兼容排查见 [快捷键排查](shortcut-troubleshooting.md)；不要在普通 Shell 提示符测试，它可能触发 SIGQUIT。自动化覆盖真实 Pi 渲染器，但仍需实体终端、IME 和真实 Provider 验收。
