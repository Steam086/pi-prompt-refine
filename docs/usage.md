# 使用说明

安装与最小流程见 [README](../README.md)。以下补充交互细节；配置字段见 [配置参考](configuration.md)。

## 触发、查看与重新优化

默认全局入口为 `Ctrl+\`（Control + 反斜杠，不是 Command）。

| 当前状态 | 入口行为 |
| --- | --- |
| 没有工作流记录，已选模型且草稿非空 | 启动后台优化 |
| 生成中、结果就绪或上次失败，编辑器仍是该请求原文 | 打开当前面板，不重复调用模型；同稿重试用 `r` |
| 编辑器已改为另一份非空草稿 B | 优化 B，取消尚未完成的 A，忽略 A 的迟到结果 |
| 已接受结果，编辑器仍是已接受文本或该请求原文 | 查看已接受的只读快照，不重复优化 |
| 等待发送确认 | 只打开面板，不替换正在确认的发送 |
| 未选模型或草稿为空 | 打开操作面板，不发请求 |

关闭面板不取消后台任务；完成时只更新摘要，不自动弹窗。修改编辑器本身不发请求，再按优化快捷键才按当前草稿判断；比较保留空白与换行，不做语义猜测。面板 `r` 明确重新优化当前主编辑器；`/refine view`（或配置的 view 快捷键）始终只查看，即使编辑器已变化也不发请求。新输入超长或模型不可用时提示未提交，并保留旧结果及其原文；相同在途请求仍去重。

### 命令备用入口

```text
/refine 待优化文本
/refine optimize 待优化文本
/refine view
/refine history
/refine usage
/refine model
/refine cancel
/refine cycle
/refine restore
```

`/refine` 不带参数也打开面板。正文保留大小写与内部空白，支持多行；若正文恰好是 `view` 等子命令，使用 `/refine optimize view`。

无参数 `/refine optimize` 读取当前编辑器，但 Pi 提交 slash command 时可能已清空编辑器，因此命令入口推荐显式携带正文。扩展会把命令原稿留回空编辑器，不覆盖已有的其他草稿，也不直接发送给主 Agent。

## 面板操作

四个顶层页面共用固定导航栏：`Preview · History · Usage · Settings`。`←` / `→` 按此顺序循环切换（Preview 按 `←` 可直接到 Settings），包括 History / Usage 的详情页；Settings 内先切换相邻分组，到外侧边界才切页（Context 按 `←` 到 Usage，Optimizer 按 `→` 到 Preview）。没有 Optimizer 分组时仍直接切页。不再使用 `h/u` 切页。切页不调用模型、不修改主编辑器或活动候选。Input / Revise 是编辑子页面，左右键仍移动光标。

以下字母键只在 Main 页生效；普通 Enter 不发送候选。完成态底栏集中展示 `a Accept`、`e Edit`、`f Revise`、`s Send`，以及 `i Input`、`m Model`、`g Same input`、`q Back` 和 `? Help`（依状态与宽度精简）；其余按键仍有效，完整说明在 Help 中。Accept 只放入编辑器、Send 才发送的说明移至 Help。顶部页签提示左右切页，候选行只展示候选位置、来源与 thinking，不重复操作提示。生成中突出 `x Stop`；已接受快照不显示候选操作，发送待确认时不再提示接受、编辑、修订或再次发送。

| 按键 | 操作 |
| --- | --- |
| `a` / `e` / `s` | 接受到主编辑器 / 独立微调候选 / 明确发送 |
| `f` | 输入修改要求，再次调用模型修订当前候选 |
| `x`（兼容 `d`）/ `z` | 生成中停止请求并保留本次任务；非生成态丢弃活动任务 / 恢复上次接受前的草稿 |
| `r` / `m` / `c` | 重新捕获并优化当前草稿 / 选择优化模型 / 循环本任务模型、可用收藏和当前模型 |
| `g` | 使用本次原稿及冻结输入，追加一个候选，不读取当前编辑器 |
| `[` / `]` | 浏览当前模型的上一份 / 下一份候选 |
| `←` / `→` | 循环切页；Settings 内先切相邻分组，外侧边界再切页 |
| `o` / `v` / `?` | 展开原稿 / 切换 Markdown 与纯文本 / 展开帮助 |
| ↑↓ / Page Up / Page Down | 滚动正文 |
| `i` | 进入 Input 页 |
| `q` / Esc / `Ctrl+\` | 返回主编辑器，保留候选和后台任务 |

- **Input**：输入的是新草稿，不是对上一候选的反馈。Enter 提交优化，Shift+Enter 或 Ctrl+J 换行，Esc 返回；提交不改主编辑器、不发送。输入稿在同一扩展运行期内按 Pi session 隔离保存在内存中；返回、关窗重开、选择模型、提交与请求结束都不清空，按 `i` 可继续修改，主动清空也会被记住。重开仍进入 Preview，不回填主编辑器；后台完成不打断 Input 编辑。reload、退出或宿主重建扩展运行时后清除，不写磁盘。Input 再次提交使用当前稿与当前上下文开始新任务；`g` 始终复用已有任务的冻结输入，不读取后续 Input 修改。
- **Revise（`f`）**：只对当前未接受、未发送的候选开放。输入修改要求，Enter 发起一次修订，Esc 返回不调用模型；输入与 Input 页独立。请求携带最初草稿、最新候选、本次要求，不无限累积优化对话。成功后追加并选中新候选，保留旧版及修订来源；失败、无效输出或超时保留之前候选，可再次按 `f`。候选或会话在输入期间变化则拒绝旧操作；重新进入时新候选不会沿用旧反馈。接受/发送仍须明确操作。
- **Main / Preview**：独立标题、状态行与统一的四页导航栏；正文标题和底部按键与设置页使用同一套中性色样式。↑↓滚动正文，标签与操作区固定。
- **Settings**：参考 Codex CLI 的横向分组和三列表格；`→` 从 Context 切到 Optimizer，`←` 返回 Context，`Tab` 仍循环切组；分组外侧边界继续切换顶层页面。↑↓在当前组内选择，默认 Shift+Tab 仍用于切换 thinking。切换分组或用左右键切换顶层页面会保留焦点和未保存的 Context，不会自动保存。Settings 中 Esc / `q` / `Ctrl+\` 返回并丢弃未保存 Context；退出整个工作区也会丢弃未保存 Context。窄屏隐藏说明列，更窄时改为紧凑行，当前项详情保留在底部。
- **Settings / Context**：Enter / Space 操作当前项；`Project instructions` 在 `First request only`（每个新任务首次包含，Revise 省略）、`Always`（每次包含，默认）、`Off`（始终关闭）之间循环，目录树与技能仍为复选项。修改仅暂存，任意行按 `Ctrl+S` 保存 Context 并返回；设置对后续请求持续生效，不改变已有结果或正在执行的请求。`q` / Esc / `Ctrl+\` 返回，只放弃未保存的 Context 修改。默认包含目录树，不包含技能元数据。
- **Settings / Optimizer**：模型选择确认、thinking 切换、编辑策略独立确认后立即生效并尝试持久化，不受 Context 保存或取消影响，主会话不变。没有可用模型或模型的 thinking 等级固定时，该行显示禁用原因且不能切换。宽屏同行显示选项说明，完整说明与长值放在固定详情区，↑↓只在选中项越过可见区域时滚动。
- **阅读**：生成中 Main 默认显示本次提交的原文快照，不随主编辑器变化；主编辑器不同会提示，修订还可查看本次修改要求。长原文在固定高度视口内换行、滚动，顶部显示可见行范围，↑↓ / Page Up / Page Down 可读全文；状态和操作区不随正文滚走。窄屏减少辅助文案，极低窗口优先保留状态与返回键。完成后默认显示候选，`o` 查看原稿；失败保留本次原文便于核对。摘要最多 6 行正文。展示转换不改变接受或发送的文字。用量只显示响应提供的计数，不估算缺失值；Preview 默认只展示 total / in / out，缓存与 reasoning 明细仍保留在 Usage 和 Help 中。

## 接受、发送与恢复

接受会写入编辑器但不发送；独立微调只改候选。编辑器草稿已变时，接受或恢复需要覆盖确认，确认返回后再次检查文本与会话。

直接发送只发送当前候选，保留编辑器中的草稿；主 Agent 忙时以 `followUp` 排队，不默认打断。请勿因原稿仍在输入框而误重复提交。Pi 接收/排队确认不代表模型已处理完成。

接受后，查看入口仍展示只读快照，`a/e/f/s` 禁用；若编辑器已改成新的非空文本，优化快捷键会优化当前修改稿，也可在面板明确按 `r`。编辑器仍是已接受文本时，快捷键只查看，不循环优化。活动任务和恢复记录只在内存中，提交消息、会话/分支切换、reload 或退出后清除；只读历史可以在同一运行期、同一 session 内跨消息与分支查看，不会重新激活旧任务。

## 多模型候选与历史（本地试用版）

同一个活动任务保存最初原稿、首次准备完成的 JSON 输入和系统模板。`m` 选择模型时不调用模型、不丢弃已有候选；目标模型已有候选时恢复上次选择，没有时显示空态。`c` 循环本任务请求涉及的模型、可用收藏和当前模型。已产生记录的模型即使后来不可用，也可通过 `c` 回看；生成前重新校验可用性。

`g` 使用冻结输入与模板，按当前优化模型、实际 thinking 和当前输出预算追加生成；不会重新读取编辑器、历史、项目规则或扫描目录。`r` / Input 则重新捕获输入并开始新任务。因此接受 A 后想让 B 独立优化最初原稿，应切模型后按 `g`，而不是 `r`。设置变更不会改写 `g` 的冻结输入；要应用新模板或上下文设置用 `r` / Input。首次输入准备未完成时没有可复用快照，需重新捕获。

`[` / `]` 在当前模型的候选中循环，切换本身不写编辑器、不发请求。接受的是当前选中的候选；已接受版本只读，其他未接受版本仍可选择。`e` 保存手工编辑版本，保留模型原始输出；`f` 使用当前选中候选及本次修改要求生成新版本，标注父记录。候选正文的阅读位置会在切换与重新打开面板时恢复。

本版仍限制一个在途请求。生成或发送待确认期间暂停模型/候选切换；生成中 `x` 只停止本次请求，保留任务与已有候选并留在面板。`/refine cancel` 仍清除活动任务，旧记录留在 History。

History / Usage 与主界面共用一个最多 100 条记录的内存日志，按宿主 session ID 隔离，列出本次加载以来该 session 各分支的记录（新到旧）。History 展示有候选的记录；Usage 展示请求，包括失败、取消、超时，不将手工编辑计作模型调用。记录可能因保留上限淘汰；没有磁盘持久化，reload、退出以及宿主重建扩展运行时时清除。

- History 每条记录占一行：草稿摘要左对齐，模型名右对齐，空间足够时显示一个状态标签（如 Accepted / Revised / Edited）；不再显示 `T1 #1` 前缀。Provider、任务与记录编号、父记录及完整状态保留在详情中。
- Usage 同样采用单行列表，对齐显示请求摘要、状态、耗时、总 Token 和模型名；`Total tok` 仅取 Provider 返回的总数，不把输入、输出或 reasoning 相加推算。`—` 表示未提供，`0` 表示明确返回零。Enter 可查看完整用量明细。窄屏逐步省略次要列，长摘要和模型名用 `…` 截断，不增加记录行数。
- `↑↓` 选择，Page Up / Page Down 按可见记录数翻动，Enter 查看；详情中 `↑↓` / Page Up / Page Down 滚动，`[` / `]` 换记录，`o` 切原稿与结果。
- `←` / `→` 在四个顶层页面间切换，详情页也适用；Esc / `q` 从详情回列表，再返回 Preview。`h/u` 和 Tab 不再切换 History / Usage。
- 浏览期间 `a/e/f/s/m/c/g/r/x` 不执行主界面操作。返回后保持原模型与候选；没有“恢复旧历史为活动任务”功能，也不会把日志自动传给模型。
- 已生成、接受到编辑器、明确发送分别记录；“Pi 接收发送/排队”不等于主模型已处理。普通编辑器提交不推断为某个候选的明确发送。
- Token 只展示 Provider 实际返回的字段；列表缺失显示 `—`，详情中完全无用量时显示 unknown，取消后迟到的用量可更新日志，但不会复活候选。History / Usage 是打开时快照，重新打开可刷新。

当前仅支持单栏阅读、原稿对照及快速切换，尚无固定 A/B 基准、diff 或双栏比较。`/refine usage` 暂时打开只读界面，不向宿主对话追加用量消息。

## 会话名称

未命名会话可在同一次优化中返回候选名称，预览单独展示，不混入 prompt。只有成功接受或 Pi 确认发送/排队后才应用名称；等待期间已有的手动命名不覆盖。无效可选名称不影响有效 prompt，恢复草稿不撤销名称。

命名由 Pi 元数据持久化；曾经命名后即使主动清空，也不会再次自动命名。

## 模型、兼容性与排查

首次安装/加载时若尚未配置优化模型，扩展提示 `/refine model`，不自动选择主模型，也不自动请求或下载模型。取消选择不写配置；没有可用模型时先在 Pi 配置 Provider 和认证。首次选择成功后提示开始方式；若配置保存失败，会明确说明仅当前进程生效。

`/refine model` 展示 Pi 已授权的 chat 模型，可搜索 provider、名称或 thinking 能力；不受主会话 scoped-models 列表限制。默认 Shift+Tab 循环所选模型支持的思考强度；未设置扩展覆盖时继承当前 session，宿主未提供则使用 `medium`，再按模型能力调整。不会改变主会话模型或 thinking。

`Ctrl+\` 已在 Pi 1.4.0 键解析器中验证，但终端、键盘布局和其他扩展仍可能拦截。用 `/hotkeys` 检查当前绑定，或使用显式文本命令。不要在普通 Shell 提示符测试该键，它可能触发 SIGQUIT。更多见 [快捷键排查](shortcut-troubleshooting.md)。

本扩展只处理可获取的文本，不承诺保留附件、光标或选区。真实终端观感、IME 和真实 Provider 效果尚需验收；UI 取舍见 [TUI 说明](ui-refinement.md)。
