# Refine 默认保守策略：修改与 IFEval 回归

后续结果见[扩展实测与费用对比](ifeval-conservative-policy-random12.md)：新增 Luna medium 的 12 题中，当前策略 Strict 为 19/24、原稿为 23/24；再新增的另一批 12 题中，Terra high／medium 的当前策略均为 24/24。批次不同，不能跨样本排名模型；本页六题结果也不能外推为无损保证。版本差异、失败调用及 Terra 批次的不活跃 UI 源码变更例外已在报告单列。

## 改动范围

只修改 `src/context.ts` 的 `REFINE_SYSTEM_PROMPT` 两处，不更改固定角色协议、JSON 输出、输入选择、模型参数或执行流程：

1. 首次 `refine` 仅为解决具体的理解／使用问题，或落实适用的明确编辑要求而修改；否则逐字返回。不因单纯的风格润色而改写或重排，需要修改时仅改必要部分。
2. 明确保护引用原文、示例与字面分隔符，包括其标点；保留用户明确要求修改字面内容的例外。

两个只读子任务分别分析修改门槛与字面内容边界，综合后选择局部补充，没有采用整套协议重写、强制结构化或追加主 Agent 自检步骤。首次修改门槛限定于 `refine`；`revise` 仍遵守明确修订要求。该策略不等于永远原样返回，也不是本地免调用旁路。已有自定义 `systemPrompt` 不会自动替换；重载扩展后，新默认策略用于后续捕获，不追溯改写既有运行。

## 实验设置

使用[前次实验](ifeval-20261109/README.md)固定的 6 道 IFEval：202、1251、3608、2563、1746、3287，共 8 项检查约束。未重抽题，也未围绕实验成绩继续调整生产模板。

- 三组：原稿直接执行、旧默认策略 Refine 后执行、新默认策略 Refine 后执行。
- 每题每组两次独立采样，36 次主模型执行、24 次 Refine，共 60 次生成；不复用前次输出。
- 旧策略从提交 `a1bd073918478d3410a6963f0919426810383047` 提取，通过 `systemPrompt` 配置注入；新组使用内置默认策略。两组其余代码与固定协议相同。
- Pi 1.5.0 的真实 TUI：`/refine optimize` → 工作台接受 → Enter 提交；每题、每组、每次重复均为独立进程和会话。
- Refine：`openai-codex/gpt-6-luna`、thinking `high`；执行模型相同、thinking `medium`。无 Preferences、无历史、关闭项目背景、预先命名。
- 执行阶段无工具、MCP、项目规则、技能或模板；所有组使用相同的真实工作目录。通过导出会话核对主模型系统提示完全相同、单条用户输入等于被接受的结果。
- 使用前次固定提交的官方 IFEval scorer，源码哈希与前次一致，`langdetect` seed 为 0。始终根据原题与原 kwargs 评分，不修改检查器。

### 环境校验失败的先行运行

`20261109T033041Z` 的 60 次生成完成后，系统提示相等断言失败：六个独立临时工作目录导致系统提示的 `cwd` 不同，其余部分相同。这批记录保留，但不计入受控比较。

仅将 runner 改为共享真实工作目录，保持生产模板不变，重新生成所有组与两次重复。正式结果来自 `20261109T033630Z`，不是挑选或拼接两轮输出。另有六项独立 SDK 检查，因此两轮任务评测与 SDK 检查共执行 126 次生成（不含子任务讨论）；前一轮的开销不能隐去。

| 指标 | 原稿直接执行 | 旧策略 | 新策略 |
| --- | --- | --- | --- |
| 改写稿逐字原样返回 | 不适用 | 7/12（58.3%） | 10/12（83.3%） |
| Strict 整题通过 | 5/12（41.7%） | 5/12（41.7%） | 7/12（58.3%） |
| Loose 整题通过 | 6/12（50.0%） | 7/12（58.3%） | 7/12（58.3%） |
| Strict 单项通过 | 9/16（56.3%） | 9/16（56.3%） | 11/16（68.8%） |
| Loose 单项通过 | 10/16（62.5%） | 11/16（68.8%） | 11/16（68.8%） |
| Refine token | 0 | 16,851 | 17,838 |
| 主模型 token | 9,954 | 9,561 | 9,567 |
| Refine＋执行 token | 9,954 | 26,412 | 27,405 |

以同题、同重复编号配对：新组相对原稿 Strict 新增通过 2 次、退步 0 次，Loose 新增通过 1 次、退步 0 次；相对旧策略 Strict 新增通过 2 次、退步 0 次，Loose 无变化。

**本次小样本没有观察到新策略损害 IFEval 下游表现，且原样返回更多。但新增通过均发生在新组原样返回的题目上，不能把分数提高归因为改写收益。** 新策略没有消除额外调用成本，Refine＋执行 token 仍约为直接执行的 2.75 倍；输出中的 reasoning 已包含在总 token 中，不重复累加。

人工核查未发现新组删除明确硬约束或扩大执行权限，但 3608 仍有非必要改写，不能把 10/12 解读为全面解决。保留这一失败边界，不继续围绕这六题调参。旧组共五次改写，其中 2563 一次改变引用的排版，3287 两次改写分隔说明；这些编辑与下游失误之间没有被本实验证明存在因果关系。

前次 README 对 2563 的标点描述不够准确：原题书名后是引号与冒号，不是引号外的句点；前次改写在书名引号内新增句点。此处依据原始输入核对，不改变前次官方分数。

## 补充验证与边界

`test/refine-policy.live.test.ts` 使用六项合成输入直接调用真实 Provider，全部通过：清楚请求原样返回、条件结构偏好不强制改写、翻译不改变回答语言、明确修改引用字面量、整合兼容任务要求、Revise 明确格式修改。该 SDK 测试使用显式系统提示，不注入 cwd，不受上述 TUI 环境问题影响。

离线检查：`npm run typecheck` 通过；`npm test` 为 1026 项通过、19 项默认跳过（包括显式 opt-in 的真实模型测试）。模板字符串断言只证明规则存在，不证明模型遵循。

六个独立题目、每组两次采样不足以建立统计非劣效性，重复不等于新增题目。IFEval 主要检查显式格式约束，不证明内容质量或真实草稿改写收益；人工语义核查也不替代原始官方分数。此次结论只适用于这组小样本回归。
