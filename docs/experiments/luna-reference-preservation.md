# Luna：原稿内 TUI 参考被误删

2026-11-09，独立 worktree `fix/luna-reference-preservation`。使用用户给出的 17 行 Preferences 界面文本及其末尾讨论问句作**合成回归样例**（`test/fixtures/reference-preservation.ts`），不读取私有 Pi session。一次请求 = 一个模型返回，不重试直到通过；使用本地 `openai-codex/gpt-6-luna`、无工具、空会话／项目背景、`maxTokens: 8192`；分别覆盖 `medium` / `high`，以及有／无当时手动选用的两条最小编辑偏好。初始原始请求的冻结背景不在 sidecar 中，因此实验不是历史请求的逐字复现。

## 定位与对照

1. 离线验证 `buildRefineInput` 将**整份**截图原样序列化在 `draft`，并与 `editing_instruction`、`conversation`、`project_context` 分开；不是输入裁剪导致的丢失。旧 `parseRefineOutput` 只验证 JSON、非空字符串，不检查源内容。
2. **旧模板**的四次独立模型调用（medium/high × 有/无偏好）都返回只含问句的短结果，整段 TUI 消失。原始模板中的“避免重复背景”“仅选必要上下文”没有明确排除 `draft` 内部参考；这是最直接的协议歧义。不能从模型输出推断其内部推理的唯一原因。
3. **仅澄清固定协议**：强调完整 `draft` 不是额外会话／项目背景，并限制删改权。首次对照 high 2/2 保留，medium 0/2 保留。说明分界措辞有帮助但不足。
4. **再强化默认编辑策略**：明确完整交付原稿，复制贴入的多行参考，无法保留则返回原稿。随后 12 次调用：high 6/6 保留整段可见 TUI；medium 4/6 保留、2/6 仍完全丢失（个别保留结果调整首行缩进或问句换行）。说明仅靠提示词无法稳定保证 medium。
5. 因此增加窄范围防护 `preserveDroppedTuiReference()`：仅首次 Refine，原稿有至少三条足够长的 `│` 行、模型结果短于原稿一半且丢失大半这些行时，保留原稿作为候选、提示用户并不使用原模型标题。识别出显式要求移除整份截图／参考材料时不拦截；Revise 不受影响。离线单测覆盖短结果、保留、显式删除、讨论删除、非截图和部分改动；扩展集成测试覆盖最终候选与通知。
6. 加防护后 8 次 live（各变体重复两次）**最终结果 8/8 保留整段可见截图**，该组模型原始输出也恰好 8/8 保留；另一组 4 次正常调用中 medium 无偏好再次丢失、由防护回退原稿，证明防护不是纯冗余。另跑的两条明确“删除整个截图”分别在 medium/high 保留了删改许可，均仅输出问句、未触发回退；两条“截图只在无关历史、不在原稿中”的 medium/high 请求均未把截图带入最终 prompt。同组有一条 high 请求遭遇 Provider overloaded、stopReason=error；它是传输失败而非内容回归通过或失败。

### 结论与限制

- **根因定位到边界约定不清 + 非确定性模型输出 + 缺少内容保真检验**：请求输入未丢截图，模型有时把内嵌参考视作可删背景，旧校验只检查 JSON。不能断言某句模板或推理等级是唯一因果。
- 固定协议的边界声明对自定义编辑策略也生效；默认策略加强了完整返回。窄防护兜住本例的整段 TUI 丢失，避免把“只剩问句”当作成功改写。**不保证**其他截图布局、日志／代码、部分行遗漏、所有语言的显式删改请求或更广义语义保真；也不应把任何文本缩短都视为错误。疑似误判保留原稿并提醒，比静默丢失参考更保守。
## 合并前验收修正

- 原删除例外的正则有可复现缺陷：`不要删除截图`、`Do not remove the screenshot`、删除疑问和删除截图中某个 UI 元素都可能被误判为允许丢弃整份参考；位于截图前的删除要求又会被漏掉。新增用例在修正前 9/9 失败。
- 将例外收紧为少量直接的整份删除表达，检查参考行前后及初始 `editing_instruction`；不把 `Main-agent task requirements` 当作改写授权。否定／保留约束保守阻止删除例外；未知措辞仍可能回退原稿，不承诺自然语言意图识别完备性。
- 扩展警告带运行编号，忽略取消后的迟到响应；补测手选 rewrite/task 偏好的不同授权范围、接受后仍不使用丢参考结果的标题、非法 JSON／截断／工具调用／错误不得变成原稿回退，以及 Revise 不受保护器干预。
- 默认策略新增段落整体限定为 `refine`，避免首句的 `draft` 要求与 Revise 的 `previous_candidate` 输入冲突。
- 修正后 `npm run typecheck` 通过；`npm test` 为 **1059 通过，21 跳过**（live 默认跳过）。本轮验收没有重新调用真实模型；上文 live 数字是调查阶段记录，不是本次复测结果，也不是原始请求的逐字重放。
