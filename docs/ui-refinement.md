# TUI 局部优化说明

## 当前结构

基于 `src/preview.ts`、`src/workspace.ts`、`src/panel-layout.ts` 的代码与渲染测试：当前 UI 是限宽单栏工作区，共用固定高度的头部、正文视口和操作区。Preview 在生成中阅读提交原文，完成后阅读候选结果；History / Usage 只读回看候选与请求，Settings 管理上下文和优化器，Input 编辑新的优化请求。四个顶层页面统一用左右方向键循环切换，输入子页保留光标键语义。完成态的原稿、帮助和源码按需展开；状态区与编辑器中的实际草稿不是同一份内容。

## 参考原则与取舍

参考 `../pi-agents-tui/Pi-TUI-Guidelines.md`，采用以下适用原则：

- 工作区顶部增加主题分隔线，与 session 内容明确分开；主页面、设置页和输入页共用，极低窗口优先保留正文与操作。总高度与页面切换时的布局保持稳定。
- 用文字和主题样式共同识别当前页面，不只依赖背景色。页签不使用中括号，以留白分隔；四个顶层页面共用 `Preview / History / Usage / Settings` 页签与两端箭头，由 `workspaceTabs()` 统一渲染，活动页使用中性背景和粗体，其他页弱化；窄屏只显示活动页。各页保留独立标题和状态行，Settings 在顶层页签下另有紧凑的 Context / Optimizer 分组。导航已标识 Prompt Refine 时，状态行不重复品牌。
- 保持导航项位置稳定。设置中的长模型标识截为单行并用 `…` 标明省略，详情显示在列表下方固定区域；选中项变化不插入或移除导航行。保留滚动位置，仅在选中项越界时最小幅度滚动；模型选择器交互不变。
- 状态应诚实且可见。发送待 Pi 确认不等于已送达，固定头部保留 `Send pending · draft kept`，不因正文滚动消失。
- 生成中展示请求启动时捕获的字面原文，不把实时编辑器内容当成已提交内容；编辑器不同则提示。长原文复用固定高度的滚动视口，显示可见行范围而非无标记地截断，状态和操作区仍固定。短原文完整展示；窄屏省略等待说明并缩短差异提示，避免说明挤掉原文。完成时重置到结果开头，原文恢复按需查看。
- 滚动位置属于辅助信息。滚动时保留模型元数据；通知优先于滚动计数显示。
- 保持主题兼容和终端列宽约束，不引入固定 RGB 或字号。

不采用参考项目的双栏、圆角外框、项目身份色、近全屏尺寸及会话导航语义。保留本项目的阅读宽度、固定视口、保存时机、模型调用及发送逻辑；顶层左右键按 Preview → History → Usage → Settings 循环切换，History / Usage 详情页也适用；不再使用 h/u 切页。Settings 内 Tab 切组，默认 Shift+Tab 保留 thinking 操作；Esc / q / Ctrl+\ 返回。跨顶层页面保留未保存 Context，不自动保存；在 Settings 取消或关闭工作区时丢弃。

## 快捷键与设置文字层级

- 空状态将 `No result yet.` 与下一行弱化的模型名组成正文中的居中信息块，不再紧贴导航；头部第二行留空，仅用于通知。窄小窗口退回有界换行与滚动，生成中和已有结果的布局不变。不显示无意义的 `Context: not captured` 或重复操作提示。`r` / `m` / `i` 集中在底部；没有任务或候选时不提示 Cancel。帮助仍保留完整操作说明。
- 完成态底栏仅突出 `a Accept`、`e Edit`、`f Revise`，导航行保留 `q Back`、`? Help`。正文用弱化说明区分接受到编辑器与 `s` 直接发送；`Enter won't send`、原稿查看、新输入、取消/丢弃等完整说明移入 Help，按键功能不变。生成中突出 `x Stop`，已接受快照不显示候选操作，发送待确认时不显示接受、编辑、修订或再次发送提示。主页面两行独立适配列宽，避免主操作的长标签挤掉返回和帮助；仅一行底栏时先保留返回、帮助，再按空间补充当前主操作。
- 主页面、Settings、Input、Help 和模型选择器共用按键样式：按键为 `text` + 粗体，说明为常规 `muted`。快捷键按终端可见列（包括 ANSI、中文和宽字符）测量；需要时按列对齐，空间不足时省略完整提示，紧凑提示与单行回退保持相同样式。Settings 优先保留固定保存键和明确的取消范围。
- Settings 的 Enter / Space 只操作当前项；Context 的项目规则支持 `First request only` / `Always` / `Off` 三态，目录树与技能仍为复选项；修改暂存，固定 `Ctrl+S` 在任意行保存 Context 并返回。底栏明确显示 `Save context`；有暂存修改时显示 `Discard context changes`，不会暗示撤销已生效的 Optimizer 设置。保存异常保留选择以便重试；配置写入失败但已在进程内生效时仍明确提示未持久化。
- 设置页参考 Codex CLI：标题、保存状态、横向分组标签、名称 / 当前值 / 说明三列，以及底部按键提示。`Tab` 切换分组并保留各组焦点；`←` / `→` 与其他页面一样切换顶层页面，↑↓只在当前组内循环。Context 状态行显示 `Ctrl+S to save · Applies to future requests`，Optimizer 显示 `Changes save on confirmation · Applies to future requests`；未保存提示和保存错误优先。模型选择和提示词编辑在确认后保存，thinking 切换立即保存。
- 目录树和技能的值使用 `[x] On` / `[ ] Off`；模型、项目规则和编辑入口带有尾部箭头。thinking 不可用时弱化显示，Enter / Space 与 thinking 快捷键均不能更改。
- 设置列表根据正文宽度适配：76 列起显示三列，56–75 列显示名称和值，更窄时使用紧凑行。每行高度固定，长值截为单行并显示 `…`，底部详情区正常为两行，短窗口缩为一行，极低窗口优先保留当前项。设置页与其他页面总高度一致。
- 标签使用 `text`，值与说明使用 `muted`；选中行的标签加粗，值和说明使用 `text`，整行使用 `selectedBg` 背景及前导箭头。活动组使用 `toolPendingBg` 中性背景。沿用主题颜色，兼容明暗主题；文字先截断再着色，避免 ANSI 重置切断高亮背景。

- 主页面的正文标题、Markdown 标题与 Input 标题统一使用中性文字色和粗体；完成、失败与发送待确认仍保留语义色。主页面的分组标签固定在正文上方，长文只滚动内容；窄低窗口压缩或隐藏标签留白，保证可见内容和返回操作。
- Settings 的 Enter 提示统一为 `Change`，不可操作的 thinking 显示 `Unavailable`。宽屏 Context 的底部固定展示规则模式和目录 / 技能说明，逐项解释留在同行，因此上下移动只改变前后两条焦点行；窄屏继续显示当前项详情。
- 设置帧使用有界缓存；配置、保存状态、外部刷新内容、尺寸和主题变化会使缓存失效。上下移动不再查询模型注册表；打开设置、宿主刷新和 thinking 保存后刷新模型快照。主页面只在正文相关状态变化时重建正文缓存，elapsed time 与 notice 更新不重新排版长文本。

## 验证边界

自动化覆盖四页双向循环、统一活动页签、h/u 不再导航、详情页切换、输入光标键隔离、跨页暂存 Context、跨页面按键样式、Settings 保存/取消范围、任意焦点下的固定保存键、保存异常重试、thinking 禁用状态与快捷键保护、区域说明与完整行高亮、两行提示对齐、ANSI/宽字符列宽、Optimizer 和模型列表的明暗主题样式与字重调用、活动页样式、窄屏页名、长模型导航行、滚动元数据及待发送状态；原有测试覆盖明暗主题、Unicode 列宽、焦点、页面切换和真实 Pi 渲染器的终端输出捕获。尚未进行真人终端视觉、IME 或不同终端模拟器验收。极窄或极低窗口仍受可用行列限制，不承诺完整展示所有元数据与辅助说明。

## Settings 导航测量（2026-11-03）

使用 Node v24.18.0、真实 Pi `TuiMainScreen` / `TuiAltScreen` 渲染器及真实调度器，在模拟终端写出回调记录输入回调到首次 `terminal.write` 的延迟。每组连续上下移动 120 次，丢弃前 20 次预热。此测量不包含操作系统键盘重复延迟、终端模拟器实际绘制、远程连接或宿主长会话内容的成本。

以下为横向分组改版之前、完成三态配置时的历史单轮测量；数字受调度与运行环境影响，不作为 CI 的时间阈值。变化行数比较去除 ANSI 后的整行文本，包含选中箭头、详情和快捷键提示，不等同于移动的选项数。

| 模式 / 尺寸 | 中位延迟 ms（前 → 后） | P95 ms（前 → 后） | 每键变化行数（前 → 后） | 每键字节数（前 → 后） |
| --- | --- | --- | --- | --- |
| regular 40×24 | 0.237 → 0.278 | 0.397 → 0.488 | 7.4 → 3.8 | 822 → 958.2 |
| regular 80×40 | 0.248 → 0.270 | 0.307 → 0.339 | 2.6 → 3.8 | 823.4 → 1279.9 |
| regular 100×40 | 0.243 → 0.251 | 0.307 → 0.299 | 2.6 → 3.8 | 879.4 → 1347.9 |
| fullscreen 40×24 | 0.229 → 0.241 | 0.294 → 0.297 | 7.4 → 3.8 | 741.8 → 534.1 |
| fullscreen 80×40 | 0.267 → 0.259 | 0.355 → 0.309 | 2.6 → 3.8 | 469.6 → 612.7 |
| fullscreen 100×40 | 0.272 → 0.274 | 0.321 → 0.313 | 2.6 → 3.8 | 489.6 → 632.7 |

修改前后全部测量均为 0 次全屏重绘，未复现明显的软件渲染阻塞。此次优化主要减少窄窗口中的布局跳动：固定导航行与详情区，取消选中长值时插入行，并保留滚动位置。最终窄窗口平均变化行数从 7.4 降至 3.8；较宽窗口会额外更新详情，普通模式输出字节数有所增加，因此不宣称所有尺寸的渲染速度或流量均有改善。

## 统一主界面与导航缓存复测（2026-11-03）

在上一版横向 Settings UI 的基础上，使用同一进程调度方式、真实 Pi 渲染器与模拟终端，对 Context、Optimizer 和 500 段 Markdown 主页面上下滚动分别测量。覆盖 regular / fullscreen、40×24 / 80×40 / 100×40，每个场景 120 次移动，丢弃前 20 次预热。下表为 100×40 的单轮结果，时间单位为 ms。

| 模式 / 场景 | 中位延迟（前 → 后） | P95（前 → 后） | 每键变化行数（前 → 后） | 每键字节数（前 → 后） |
| --- | --- | --- | --- | --- |
| regular / context | 0.185 → 0.027 | 0.222 → 0.041 | 3.6 → 2 | 1199 → 499 |
| regular / optimizer | 0.185 → 0.027 | 0.219 → 0.039 | 4 → 3 | 1381.3 → 885.3 |
| regular / preview | 0.252 → 0.239 | 0.306 → 0.275 | 19 → 16 | 3521.5 → 3090.5 |
| fullscreen / context | 0.211 → 0.040 | 0.262 → 0.058 | 3.6 → 2 | 703.8 → 469.6 |
| fullscreen / optimizer | 0.205 → 0.037 | 0.249 → 0.057 | 4 → 3 | 748.9 → 595.9 |
| fullscreen / preview | 0.275 → 0.256 | 0.326 → 0.291 | 19 → 16 | 3611.5 → 3020.5 |

18 个场景均为 0 次全屏重绘。Context 的宽屏导航只更新两条焦点行；Optimizer 保留按项变化的完整值详情，统一 Enter 提示后减少了底栏重绘。缓存命中时无需重新构造设置帧，也不访问模型注册表。主页面新增固定标签会减少三行正文视口，滚动字节数的下降部分来自可见行减少，不能全部归因于缓存。

额外回归检查验证了进度时间与通知刷新不调用正文排版；正文、状态、主题及尺寸变化仍正确刷新，设置外部刷新、保存反馈和禁用状态不会被缓存遮蔽。这里测量的是输入回调到首次 terminal.write，不包含真人终端、键盘重复、IME、远程链路或宿主长会话的延迟。

扩展后的复测命令仍为上面的 `REFINE_BENCHMARK=1` 命令；输出增加 `scene` 字段。默认 `npm test` 跳过性能测量，避免把环境波动作为 CI 阈值。
