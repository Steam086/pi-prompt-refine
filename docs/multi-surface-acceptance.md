# 实验 Web 插件的隔离宿主验收

这次验收使用 pi-web `1.202611.1`、Pi SDK `1.5.2`、Node `24.18.0` 和 Chrome `156.0.8078.47`。宿主、Pi 数据和浏览器 profile 均独立。优化请求只发送到确定性的本地 stub。下表记录该版本组合的表现，原始验收记录随提交 `80ba431` 入库。当前构建与测试入口见 [Web 子包](../packages/pi-web/README.md)。

| 场景 | 观察结果 |
| --- | --- |
| 加载与重载 | 宿主通过公开的 session-events capability 加载插件。客户端和服务端版本不匹配时拒绝连接。重载后旧 Binding 的写入返回 `binding-stale`。 |
| 两个 Chrome 页面连接同一会话 | 两端各有 lease，能看到对方保存的草稿。过期版本写入被拒绝，本地未提交的文本保留。原生 `/refine-api` 保存的草稿在 Web 可见。 |
| 后台运行、取消和回执丢失 | 四个运行同时生成，第五个排队。取消排队项没有调用 stub。注入回执丢失后，客户端按原作用域查询，stub 只收到一次请求。关闭阅读页后运行继续。 |
| 长文本 | 100,000 个 UTF-16 代码单元的输入、2,097,152 个 NUL 字符的结果和 300,000 字符的可读结果均完整往返。长结果可滚动，选中的 run ID 保持稳定。 |
| 请求与会话边界 | SDK 收到的改写请求没有工具，主会话消息数保持为零。宿主拒绝跨工作区会话，服务端拒绝未知路径字段及未获准的 Host、HTTP Origin 和 WebSocket Origin。 |
| 浏览器呈现 | 在 1440 × 1000 和 420 × 700 的明暗主题视口中检查了布局。实测曾发现运行回执先于下拉选项时会丢失选择，修正后经过宿主复验，并有[桥接回归测试](../packages/pi-web/test/bridge.test.mjs)。 |

这次运行只覆盖 Chrome 和本地 stub。人工中文输入法、可访问性、其他浏览器引擎、真实 Provider，以及生产部署的 HTTP／WebSocket 身份认证和 TLS 仍需单独验证。Web 子包仅供本地开发与隔离验证。
