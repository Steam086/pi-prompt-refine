# Revise Preference：手动保存、查找与复用修订要求

> 状态：首版已实现。本文保留初版设计记录，**交互方案已被简化版替代**：仅 Add / Edit / Delete 三个可见管理操作，Tab 只切三个区域，Alt+P 进入、Alt+Enter 带回，不使用功能键。原有 F2、多操作按钮及临时编辑页不再适用；当前交互以 [usage.md](usage.md#保存与复用修订要求preferences) 为准。第 12 节中的存储、快照隔离与显式提交边界仍保留。
> 实施顺序：状态设计 → 一致性 review → 代码与测试 → 提交、推送。实体终端与 IME 仍需实际验收。

相关文档：[设计原则与演进方向](../DESIGN.md#手动保存修订要求与模板复用)、[现有使用说明](usage.md#inputrevise-与-settings)。

## 1. 目标与边界

Preference 是用户手动保存的短修订要求，由名称、完整正文及作用域组成，用来减少 Revise 中的重复输入。名称用于查找，实际请求使用完整正文，不根据“简洁”“自然”等名称推测含义。

首版目标是完成以下键盘流程：

```text
保存 → 查找 → 预览 → 选择 → 本次调整 → 检查实际要求 → 提交修订
```

必须分开三个动作：

| 动作 | 推荐 UI 名称 | 效果 |
| --- | --- | --- |
| 持久化条目 | 保存到 Preference 库 | 保存可复用内容，不调用模型 |
| 用于当前修订 | 带回本次修订 | 更新本次已选项，不调用模型 |
| 发起模型调用 | 请求修订 / Request revision | 冻结实际要求并请求模型 |

避免使用没有限定语的 `Apply`：现有产品已经用它表达候选结果操作，不应复用为 Preference 的含糊动作名。

约束：

- 保存、浏览、勾选、带回都不自动提交，不写 Pi 主编辑器，不发送 Pi 消息。
- 项目／全局作用域只表示“在哪里可选”，不表示自动应用。
- 一次使用不成为默认偏好，不根据接受、发送或选择行为推断长期偏好。
- Preference 不能改写固定角色与输出协议，也不能自动扩展原任务授权。
- 保存时应区分“如何改写 prompt”和“要求主 Agent 如何回答”；具体是否增加类型字段仍待讨论，不应将两者隐式混为编辑策略。

## 2. 已确认的现有流程

以下依据讨论时的 `src/workspace.ts`、`src/prompt-input.ts`、`docs/usage.md`；实施前需要再次核对版本。

- 结果详情／Inspect 中按 `f` 进入 Revise。
- 常规尺寸下原地展开输入，上方保留来源候选和阅读位置；小终端使用完整输入页。
- `Enter` 换行，`Ctrl+S` 请求修订，`Ctrl+E` 展开／收起，`Esc` 返回。
- 输入期间普通字母及方向键交给编辑器，不触发浏览、接受或发送快捷操作。
- 修订草稿按候选身份隔离，目前仅保留在本次工作区生命周期内，最多 100 份；关闭工作区后清除。
- 提交使用绑定的候选 token，目标过期时拒绝操作。恢复记录没有完整背景，不提供 Revise。
- `PromptInput` 包装 Pi 原生 Editor；当前包装层没有提供可直接依赖的选区读取接口。
- 检查到的原生 Editor 默认将 `Ctrl+E` 用于行尾，现有 Revise 已覆盖为展开／收起；`Tab` 属于原生编辑器的 Tab／补全绑定。

这些信息不证明用户自定义绑定、其他扩展和实体终端行为相同。新增快捷键不应只根据扩展自身未占用就判定无冲突。

## 3. 入口方案比较

| 方案 | 优点 | 代价与风险 | 建议 |
| --- | --- | --- | --- |
| Revise 内专用功能键打开选择页 | 不污染正文，入口清楚，可统一搜索和管理 | 需验证终端传键、宿主及扩展冲突 | 推荐 |
| `/pref`、`@名称` 等输入补全 | 连续输入较快 | 与真实要求、路径引用混淆，粘贴和 IME 处理更复杂 | 首版不做 |
| 每条 Preference 单独快捷键 | 高频使用路径短 | 难记、易误触，数量增加后冲突难管理 | 不推荐 |
| 退出 Revise 后进入 Settings | 不占输入快捷键 | 打断修订，远离来源候选 | 仅适合作为辅助管理入口 |

### 推荐入口与键位

暂定 `F2` 打开 Preferences，仅在 Revise 内生效；建议允许改绑或关闭，不注册为任意页面都会触发的全局动作。

选择 F2 是为了避开普通文本、Tab 和常见编辑控制键，**不是已经确认它无冲突或能在所有终端传递**。正式默认键必须在核对宿主、其他扩展与终端之后确定。

建议页脚：

```text
F2 Preferences       Ctrl+E Expand
Ctrl+S Request revision   Enter Newline   Esc Back
```

非 F2 备用入口建议为结果详情动作中的 `Revise with Preferences…`，进入同一修订流程并打开选择页。

**待核实：**现有详情是否有适合承载该入口的可导航操作菜单、如何进入该菜单，以及自定义 UI 内快捷键配置方式。不能把这个菜单写成已存在的能力；若需要新增，应纳入后续 UI 设计。

窄屏不能因为提示折叠而完全隐藏 Preference 的发现入口，具体页脚布局仍需渲染验证。

## 4. 选择页：搜索、预览、多选

推荐使用独立的逻辑子页，保留原 Revise 输入和来源状态，不依赖叠加多个宿主弹窗。

宽屏采用列表加正文预览；小屏采用完整列表页，进入详情阅读全文。是否同时保留来源候选，以及切换布局的尺寸阈值，需要实际渲染后确定，不强行塞入三个狭窄区域。

示意图仅表示信息层级，不是最终尺寸：

```text
Preferences                         仅用于本次修订

搜索：简洁_
范围：当前项目 + 全局

  [✓] 简洁但保留约束       全局
> [ ] 命令原样保留         项目
  [ ] 不重复已有背景       全局

──────────────────────────────────
命令原样保留
保留所有命令、参数和代码的字面内容，
不要为了纠错、缩短或统一风格而修改它们。

已选 1 项
[带回本次修订]  [保存新条目…]  [管理…]
```

### 信息与搜索

- 列表显示名称、项目／全局作用域及已选状态；同名条目必须能区分。
- 长名称可截断，但预览应能查看完整名称与正文，不能只有摘要。
- 搜索覆盖名称、关键词和正文，名称匹配优先；首版不需要模型相关性评分。
- 可优先展示最近使用项，但最近使用不等于自动选中，后台变化不得使当前高亮跳走。
- 搜索不清除已勾选项；页内持续显示已选数量，并能检查当前搜索结果之外的已选项。
- 空库、无匹配和加载失败应区分；失败不能伪装成空库。无匹配时保留搜索输入及清除搜索入口。

### 焦点与按键建议

| 焦点／位置 | 行为 |
| --- | --- |
| 搜索框 | 普通字符输入；Enter 进入结果列表，不带回、不提交 |
| 结果列表 | ↑↓移动；Space 勾选／取消；Enter 查看完整要求 |
| 正文预览 | 方向键、翻页键滚动 |
| 操作按钮 | Enter 执行聚焦按钮 |
| 选择页 | Tab 在可用区域间切换，建议 Shift+Tab 反向移动 |
| 条目详情 | Esc 返回列表，保留搜索和暂存选择 |
| 选择页根层 | Esc 放弃本次选择变更，返回 Revise |

Tab／Shift+Tab 的导航仅限 Preference 子页，不能据此夺走 Revise 编辑器中的原有行为。实际键位与焦点顺序仍需冲突检查。

交互边界：

1. 高亮仅预览。
2. 勾选仅修改选择页的暂存状态。
3. `带回本次修订` 才更新 Revise 的本次已选项。
4. 打开选择页时以当前已选项初始化；取消则保持打开前状态，包括条目的本次临时编辑。

相较“Enter 选中后立即返回”，显式带回多一步，但能统一多选、取消与预览语义。首版优先可预测性，而非最少按键。

## 5. 已选项与自由输入

### 方案比较

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 直接把正文插入自由输入 | 所见即所得，可随意编辑 | 来源和边界丢失，难按条移除，重复选择容易重复插入 |
| 独立已选项 + 自由输入 + 实际要求预览 | 便于多选、移除、追溯来源 | 需要组合与全文预览，不能只显示名称 |

推荐第二种。已选内容是本次修订的文本快照，而非指向库内容的动态引用。

```text
Revise · 来源：模型 A / 运行 12

本次要求：
[简洁但保留约束 ×] [命令原样保留 ×]
仅本次有效 · 2 项 · 可查看／临时编辑

补充要求：
这次保留背景说明，但删除重复例子。_

[查看实际要求…]
Ctrl+S Request revision
```

上述标签和按钮是信息示意，不假定支持鼠标点击。推荐在 Preferences 子页提供可键盘导航的“本次已选”和“实际要求”视图；主 Revise 中的摘要不应要求用 Tab 抢走编辑焦点才能管理。

每个已选项支持查看全文、移除和临时编辑。临时编辑显示“本次已修改”，不自动更新库。更新长期条目必须另行“另存为”或明确编辑库条目。

库内容后来变化，不静默改动当前已选快照；修改库内容也不追溯改变已提交请求。

### 实际要求

`查看实际要求` 展示准备传给 `revisionInstruction` 的完整文本，不是再次生成的摘要。例如：

```text
保留全部硬约束，仅删除重复表达。

保留所有命令、参数和代码的字面内容，
不要为了纠错、缩短或统一风格而修改它们。

这次保留背景说明，但删除重复例子。
```

建议采用确定性拼接：按界面展示的已选顺序组合正文，再附自由输入；不让模型预先重写要求。具体顺序维护和分隔格式需在实施前固定并测试。名称、作用域等 UI 元数据默认不混入正文。

预览必须与提交使用同一份组合结果，并清楚标注：

> 这是本次修改要求；请求还会携带原稿、来源候选及现有修订流程允许的背景。

不将其冒充完整请求 payload 预览。预算校验失败应保留输入，不静默截断要求。

### 冲突处理

不保证“自由输入在后，就一定覆盖 Preference”。例如“删除背景”和“保留背景”同时存在时，让用户移除或临时修改已选项，不静默代为裁决。

首版不承诺自动识别语义冲突，不引入额外模型调用来组合或解释偏好。

## 6. 保存与管理

### 保存新条目

```text
Revise 写好要求
→ Preferences → 保存新条目
→ 编辑名称、完整正文、项目／全局作用域
→ 聚焦“保存到 Preference 库”并确认
→ 回到原修订流程，未提交请求
```

可从本次自由输入预填全文，或创建空白条目；保存表单允许删减至真正适合复用的部分，不默认混入所有已选项。

首版不依赖 Editor 选区读取：目前包装层没有可直接依赖的接口，不应承诺“选中文字直接保存”。以后核实宿主能力后再评估。

保存前提醒检查路径、一次性任务限制和敏感内容。成功后显示：

> 已保存到库；未新增应用，未提交请求。

保存动作不自动增加本次已选项，也不重复插入仍留在自由输入中的同一段文字。需要使用新条目时，由用户显式选择；组合预览帮助检查重复，首版不做语义去重。

失败时保留表单和内容，显示失败原因或可操作提示，不伪装为已落盘。取消编辑表单返回上一级；有未保存变更时应明确确认是否放弃。

### 管理与作用域

管理入口提供编辑、删除和作用域调整；删除需明确确认。管理保存与“本次临时编辑”必须区别标注。

Preference 独立于 session 历史持久化，不随单个 session 历史淘汰或清理。具体文件位置、项目身份、格式、原子写入及并发冲突方案尚未确定。

首版不提供自动默认应用。以后若增加默认项，必须由用户单独明确设置，不能从作用域、最近使用或接受行为推导。

## 7. 提交、返回与异步隔离

- 只有 Revise 编辑页的 `Ctrl+S` 可以请求模型。
- Preference 选择、预览、管理、保存表单中的 `Ctrl+S` 不透传，也不用于持久化保存；界面可提示使用明确按钮或先返回 Revise。
- Preference 子页的 Enter 不能触发模型请求。
- 完成保存／带回时消费当前输入事件，不让同一个 Enter 落入下一页。
- 子页返回后恢复编辑位置、自由输入及来源阅读位置；可恢复的光标信息需核实 Editor 接口。
- 已选快照、临时修改和自由输入共同绑定候选身份，不跨候选串用。
- 后台完成不能抢焦点或替换修订来源；提交仍须检查候选 token、session 及现有发送互斥状态。
- 目标过期时拒绝请求并保留可恢复的编辑内容，不自动改绑到新结果；跨 session 不自动迁移这份临时状态。
- 默认沿用现有临时修订草稿的工作区生命周期，不因引入 Preference 库而自动持久化未提交自由输入。

不建议每次提交额外弹确认框。可查看的实际要求、明确来源和已有 `Ctrl+S` 提交足以形成正常路径；出错或目标变化走明确的异常处理。

## 8. 关键端到端流程

### 复用

```text
结果详情 f
→ F2（暂定）
→ 搜索、预览、勾选
→ 带回本次修订
→ 添加自由输入／临时调整
→ 查看实际要求
→ 返回 Revise，Ctrl+S 请求修订
```

### 取消

```text
打开选择页 → 更改勾选 → Esc
→ 返回 Revise，保留打开前的已选项和自由输入
```

已明确保存到库的管理变更不会因为随后退出选择页而回滚；Esc 取消的是尚未带回的本次选择，不是撤销所有持久化动作。

### 临时调整

```text
带回 Preference → 编辑本次正文 → 显示“本次已修改”
→ 检查实际要求 → 提交
```

库内容保持不变。需要长期保留时另走明确保存流程。

## 9. 待核实与实施前决策

1. **快捷键：**F2 在宿主、用户自定义绑定、其他扩展及终端中的可用性；改绑方式和冲突提示能力。
2. **备用入口：**结果详情现有操作入口能否承载 `Revise with Preferences…`，必要时如何新增，不能假设已有操作菜单。
3. **焦点与 IME：**搜索中的 Enter 是否会与中文候选确认冲突；焦点切换、粘贴、按键重复及取消行为需实体终端验证。
4. **Editor 能力：**光标／阅读位置的恢复、选区读取和本次编辑撤销边界；不得仅凭包装层推测宿主接口能力。
5. **响应式布局：**宽窄屏阈值、长名称、完整正文滚动、页脚空间及本次已选管理入口。
6. **组合规则：**稳定顺序、正文分隔格式、空要求处理及预算错误提示；预览与实际提交必须一致。
7. **持久化：**存储路径、项目作用域身份、稳定 ID、库编辑冲突、失败恢复；是否需要将保存项版本／文本快照关联到分析记录。
8. **管理边界：**修改或删除库条目时，本次已选快照如何标注来源变化；不允许静默替换其正文。

## 10. 后续验收重点

- 只用键盘完成保存、搜索、全文预览、多选、移除、临时编辑、检查与提交。
- 高亮、勾选、带回、保存及 Enter 均不意外请求模型。
- Preference 子页不能透传 `Ctrl+S` 到 Revise。
- 选择页取消恢复原状态；保存失败、空库、无匹配和库加载失败均有独立表现。
- 临时修改不改变库；库更新不改动已选快照或已提交请求。
- 自由输入不被覆盖；实际要求预览与提交一致，不静默截断。
- 两个候选的已选项和草稿不串用，后台完成不抢焦点，过期 token 不能提交。
- 小终端、长正文、中文输入、粘贴、焦点恢复和功能键传递经过实际验收。

## 11. 首版不做

自动提取偏好、自动默认应用、自动记忆、自动模板改进、模型驱动的组合／冲突裁决、每条 Preference 的全局快捷键，以及完整模板组合与版本管理系统。

推荐取舍是：**用一个明确的“带回”动作换取可预测的多选与取消边界；用独立已选项保留来源，再用完整实际要求预览避免隐藏生效内容。保存只是收藏，带回只是准备，Ctrl+S 才请求模型。**


## 12. 首版实施契约与状态转换

### 数据与语义

- 库条目：`id / version / name / body / scope`。仅保存明确的修订指令；如需改变主 Agent 的回答方式，正文应明确写“在提示词中加入……要求”，不由名称推测。没有自动生效或独立类型字段。
- 候选草稿：`freeText / selected[]`，由现有 `sessionId:recordId` 身份隔离，工作区内最多 100 份。已选项保存条目身份、版本、名称、原始正文及本次正文。请求只传组合正文。
- 选择页工作副本 `working[]`：打开时深拷贝已选项。选择、移除、本次编辑都只改 working；带回整体替换 selected；取消整体丢弃 working。
- 勾选按操作顺序追加；移除后重新勾选追加末尾并重新捕获库正文。每个 scope/id 最多一项，每份草稿最多 50 项；同名不同 ID 可同时选择。搜索和库刷新不改变已选顺序。
- 组合：依序取本次正文，然后取自由输入，丢弃全空白段，以两个换行连接；非空段不 trim、不改写、不截断。空自由输入允许仅用已选项提交；总组合为空或超过 `maxDraftChars` 时拒绝。
- “当前实际要求”始终展示已带回 selected + freeText；“带回后预览”展示 working + freeText，明确标注尚未带回。两者都使用同一组合函数。预览不冻结后续修改；Ctrl+S 时冻结最新已带回状态。
- Revise 编辑器在子页停留期间保留实例，不重新 setText 或捕获目标；返回恢复原光标和撤销栈。保存预填和提交均读取展开粘贴后的完整文本。

### 存储与入口

- 全局库：Pi agent directory 下 `prompt-refine-preferences.json`；项目库：启动工作区的规范化 cwd 下 `.pi/prompt-refine-preferences.json`。项目按 realpath(cwd) 隔离，不自动上探仓库根，不合并 worktree。
- 两个文件分别使用同目录独占锁协调本扩展多进程写入；锁内重新读取并按条目 version 检查编辑／删除冲突。创建追加到最新库，不覆盖并发创建。临时文件 + rename 防止部分写入；绕过锁的外部文件写入不在并发保证内。
- 锁占用立即报告可重试错误；崩溃遗留锁不按时间自动抢占，提示确认没有写入进程后移除锁。损坏／未知版本／超限文件显示加载错误并禁止覆盖；两个作用域分别报告结果。
- 每个库文件最多 1 MiB、500 条；名称 120 字符、正文 16,000 字符。运行时组合另受当前 maxDraftChars 限制。库不包含完整背景；已提交组合正文沿用现有 history sidecar。
- 首版不做最近使用排序、独立关键词字段、原地跨作用域移动；搜索名称和正文。跨作用域复用通过另存为，原条目保留，避免跨文件事务。
- F2 默认仅 Revise 生效，配置 `preferencesKey` 可设功能键／带修饰键或 null；保留 Ctrl+S、Ctrl+E、Esc、Tab 和普通输入键。与 Pi 已解析键位冲突时禁用本地入口并提示；无法检测终端或其他扩展截获。结果页与 Inspect 增加明确 `p Preferences` 备用入口，无需假设存在操作菜单。
- 宽屏显示列表和正文预览，窄屏 Enter 进入可滚动全文。所有页使用现有 panelLayout；焦点循环包含搜索、列表和逐个操作按钮，输入内容不充当动作快捷键。

### 实施前 review 结论

逐条检查：① selected 与 working 不共享可变对象；②两种预览标题明确，不将暂存结果冒充当前提交内容；③只有 Revise 提交入口能调用模型；④库写入与选择事务独立；⑤取消不回滚已落盘操作；⑥异步完成不会切换已关闭 UI；⑦并发写入在锁内重新读取并验证版本；⑧所有正文路径使用完整展开文本；⑨快照身份与候选 token 分离，提交继续执行原有校验。以上规则消除了已发现的设计歧义，可据此开发。功能键传递、真实 IME 和极小终端可用性列为环境验收项，不宣称自动测试可以证明。
