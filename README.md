# Pi Prompt Refine

在发给主 Agent 之前，结合当前对话，把你想说的话整理清楚。

Pi Prompt Refine 是 Pi Coding Agent 的提示词改写扩展，**主要面向用户在聊天／Agent 窗口中的交互**。你可以先用自然、口语化的方式写下想法，再借助独立的优化模型梳理表达，检查结果是否准确传达了自己的意思，最后决定是否交给主 Agent。

## 用途与改写原则

目标是帮助用户快速整理思路，用适合当前对话的表达传达意图，减少初始误解。

- **先理解意图**：结合相关对话，识别当前讨论对象、问题或希望采取的动作。
- **主动整理表达**：理顺口语和松散结构，纠正病句、去除重复；上下文明确时补清指代，保留自然语气。
- **保持原有边界**：保留原意、约束和不确定性，准确区分讨论、建议与执行要求。
- **保护字面材料**：默认要求路径、命令、代码、粘贴的 TUI、日志和引用材料保持原样，同时正常优化周围的请求文字。

默认策略以忠实、清楚、自然为目标，已经表达清楚的草稿也可以保留。接受前请检查结果是否符合你的意图，以及字面材料是否完整。

## 主要功能

- 从 Pi 主编辑器捕获草稿，在独立工作台中查看、编辑和修订，任务执行交由主 Agent。
- 优化模型独立于主 Agent，复用 Pi 已配置的 Provider 与认证。
- 同一原稿可交给多个模型并行优化，共用冻结的会话背景，方便人工比较和选择。
- 支持「再短一点，命令原样保留」这样的逐次修订，以及可复用的 Preferences。
- 由你明确选择接受或发送；接受仅写入主编辑器，供你继续修改。
- 后台运行，关闭面板后请求继续，完成时保留当前焦点。

## 安装

原生工作流需要 **Node.js 22.19+**、已配置可用模型与认证的 Pi Coding Agent，以及 Pi 的**交互式 TUI**。

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

安装命令会完成包获取。安装后启动 Pi；已有会话执行 `/reload`。扩展以 Pi 进程的用户权限运行，请只安装可信来源。

## 第一次使用

### 1. 选择优化模型

首次使用时，在 Pi 中执行 `/refine model`，从已配置认证的模型中选择独立的优化模型。

可以优先尝试速度快、成本低、能力略低于主模型但足以理解当前对话的模型。以改写是否忠实、清楚作为选择依据，让优化模型专注于整理表达，主 Agent 负责后续任务。

### 2. 写下草稿，启动优化

在 Pi 主编辑器中自然地写下需求，例如：

```text
就刚才说的那个错误处理，看看 @src/ 里是不是有把异常吞掉的地方，先说说原因和建议，别直接改代码。
```

按 **`Ctrl+\`（Control + 反斜杠，不是 Command）**，将草稿作为 **Unsent** 保留并打开 Refine。选中原稿后按 **Enter** 才开始优化；也可先按 `i` 编辑，或按 **Tab → Space → Enter** 选择 Preferences 并启动。

> **快捷键用于捕获／打开，Enter 才启动优化。** 草稿未变或已捕获时定位已有条目；输入框为空时只打开工作台。发送给主 Agent 是后续独立操作。

也可以通过命令直接提交文本：

```text
/refine 看看错误处理，先给建议，不要改代码。
```

带正文的命令会直接发起优化。随后执行 `/refine` 查看结果。运行期间，主编辑器上方会显示 Refine 的运行、排队、新结果及失败状态。

### 3. 查看结果，决定是否使用

- 按 **`a`**：将选中结果放入 Pi 主编辑器，**不发送**；继续修改或自行提交。
- 按 **Enter**：查看详情；按 `e` 手工编辑，或按 `f` 输入修订要求、**Ctrl+S** 发起修订。
- 按 **`m`**：选择另一个模型，从同一原稿重新优化，供你比较。
- 按 **`q` / Esc**：返回或关闭，保留当前草稿；后台任务继续运行。

工作台关闭后可再按 `Ctrl+\` 打开。完整按键、删除记录、发送确认和恢复行为见[使用说明](docs/usage.md)。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/refine` | 打开工作台，不自动发起优化 |
| `/refine <文本>` | 直接提交文本进行优化 |
| `/refine model` | 选择默认优化模型，不改变主 Agent 模型 |
| `/refine history` | 在 Usage 中查看当前与历史记录 |
| `/refine restore` | 恢复上次接受前被替换的 Pi 草稿，必要时确认 |

更多命令见[使用说明](docs/usage.md)。

## 常用工作流

选中模型结果即可操作，按 Enter 查看详情。

| 场景 | 操作 |
| --- | --- |
| 接受 | 按 `a` 写入主编辑器，不发送 |
| 微调 | 详情中按 `e` 手工编辑 |
| 工作区 | 原生居中大浮窗，约 98% 宽／96% 高；各页共享固定外框，背景 session 少量可见，长文内部滚动 |
| 修订 | 列表选中结果或详情按 `f`，默认输入补充要求；Enter 换行，Ctrl+S 请求，Ctrl+E 切换仅编辑／显示来源；未提交要求在本次 Pi 运行期内保留 |
| 复用编辑要求 | Preview 的 Unsent 原稿按 Tab 聚焦内联 Preferences，仅 Space 勾选，Enter 直接开始优化，Esc / Tab 返回并保留选择，`o` 阅读全文；`p`（或 Alt+P）仍打开完整面板，需 Alt+Enter 带回。Revise 中选择并带回后 Ctrl+S 修订。原始任务不变，要求独立传递 |
| 切换模型 | 按 `m` 选模型，Enter 重新优化原稿 |

Preferences 可逐次手动选择，或在 `p` 的列表中按 `g` 设为当前目录的项目默认项（`*` 标记）。新原稿自动选中默认项；逐项取消或按 `c` 清空仅影响当前请求。选好后，按 Enter／Ctrl+S 显式请求模型。

任务要求类 Preferences 是对原任务的**补充**：输入时与原稿分开传递，输出时将适用且兼容的回答／行为要求融入完整 prompt，保留原任务、明确约束、条件和授权边界。当前用户明确要求的修改（如翻译 prompt 或缩小任务范围）优先生效。

Preferences 中，列表／操作栏按 `s` 检查 Selected only，按实际组合顺序显示所有已选快照，再按 `s` 恢复 All 的搜索和浏览位置。新条目保存后回到 Library 并定位，供你继续选择；必要时明确提示重置过滤。搜索支持名称／描述／正文的多词 AND 匹配，详见 [Preferences 选择与保存](docs/preference-selection.md)。

Preview 默认只展示当前轮次；全部轮次、Earlier 和恢复记录均可到右侧 Usage 查看。查看中的目标归档后继续保留当前阅读内容，Esc 返回当前列表。

结果对比、直接发送及其他操作见[使用说明](docs/usage.md)。

### 多模型比较如何工作

不同模型从**同一原稿和冻结的会话背景**独立开始改写。模型选择器支持搜索，优先展示最近使用和收藏的其他模型；比较用的模型仅作用于本次运行。每个模型会独立记住上次确认使用的 thinking 强度，包括仅用于比较的模型；下次选中后直接按 Enter 即可复用，重启后也保留。

最多同时运行 **4 个请求**，超出后排队。各请求独立取消、超时或失败；后台完成时保留当前选择和列表顺序。查看、切换或对比已有结果仅使用已生成的内容。

右侧摘要显示耗时、输入／输出 tokens 与单次参考费用，例如 `7s · ↑1.2k ↓300 · ≈$0.012`。缓存拆分、命中率和费用解释在 Usage 详情；未知费用显示 `Cost —`，订阅参考价不代表实际扣费或额度消耗。

## 上下文与数据边界

### 模型会收到什么？

所选优化 Provider 会收到草稿及已启用的背景，**它可能不同于主 Agent 使用的 Provider**。

| 背景来源 | 默认行为与边界 |
| --- | --- |
| 对话历史 | 选取当前分支的可见用户／助手文本，受条数和字符预算限制；不包含 thinking、原始工具结果或其他分支 |
| 项目规则 | 默认关闭；可在 Settings 中按需启用 Pi 已加载的规则（如 AGENTS.md），受预算限制 |
| 目录信息 | 默认目录树关闭；开启后仅在未选入历史时收集。显式 `@目录` 仍可独立收集 cwd 内的有界名称列表，不读取正文 |
| 技能元数据 | 默认关闭；启用后只提供名称和描述，不读取技能正文 |

扩展**不读取源码正文**，普通 `@file` 引用也不会加载文件内容；但先前对话中的代码可能随历史发送。优化模型没有工具，不能自行读文件、联网或执行草稿中的任务。请在使用前确认草稿和启用的背景适合发给所选 Provider；扩展无法保证识别文本中的所有敏感信息。

### 历史保存

默认将原稿、结果、已提交修订要求与运行元数据保存到 session 文件旁的 `.prompt-refine.json` sidecar（最多 100 条 / 2 MiB，权限 `0600`），**不保存完整对话背景、系统模板、项目规则或请求载荷**，不进入主模型上下文。原稿与结果本身仍可能含敏感信息。

`/resume` 或 `/reload` 后通过 `/refine history` 查看。恢复记录可接受、比较及手工编辑；若要再次请求模型，按 `i Copy to current` 复制原稿到当前 round，使用当前背景开始新的优化。

设 `historyPersistence: false` 并 `/reload` 可停用读写；`/refine history clear` 确认后删除当前 session 的保存历史并暂停保存直到 reload。删除或移动 session 时须同步处理 sidecar。保存范围及恢复限制见[使用说明](docs/usage.md#记录范围与用量)。
