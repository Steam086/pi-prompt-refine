# Pi Prompt Refine

Pi Prompt Refine 是 Pi Coding Agent 的提示词改写扩展。它结合当前对话和项目背景，帮助你把草稿中的需求表达清楚。默认策略要求模型保留原意、约束、授权范围和不确定性，只做必要的修改；已经清楚的草稿可以原样返回。

同一份原稿可以交给多个模型并行优化，再在工作台中比较各自的结果。各模型使用相同的原稿和会话背景，便于对照选择。优化模型独立于主 Agent，复用 Pi 已配置的 Provider 与认证，无需切换主会话模型。

选中候选后，你可以手工编辑，也可以提出「再短一点，命令原样保留」这样的修订要求。满意后接受到主编辑器继续修改，或明确发送给 Pi。生成结果不会自动覆盖输入或发送消息，扩展本身也不执行提示词中的任务。

优化在后台进行，你可以继续输入；关闭面板不会停止请求，完成时也不会抢走焦点。

## 常用工作流

选中模型结果即可操作，按 Enter 查看详情。

| 场景 | 操作 |
| --- | --- |
| 接受 | 按 `a` 写入主编辑器，不发送 |
| 微调 | 详情中按 `e` 手工编辑 |
| 修订 | 详情中按 `f` 提出修改要求 |
| 切换模型 | 按 `m` 选模型，Enter 重新优化原稿 |

结果对比、直接发送及其他操作见[使用说明](docs/usage.md)。

### 多模型比较如何工作

不同模型从**同一原稿和冻结的会话背景**出发，而不是接着改写上一模型的输出。模型选择器支持搜索，优先展示最近使用和收藏的其他模型；一次比较不改变默认模型设置。

最多同时运行 **4 个请求**，超出后排队。一条请求取消、超时或失败，不影响其他请求；后台完成不改变当前选择或列表顺序。查看、切换或对比已有结果不发起模型调用。

## 上下文与数据边界

### 模型会收到什么？

所选优化 Provider 会收到草稿及已启用的背景，**它可能不同于主 Agent 使用的 Provider**。

| 背景来源 | 默认行为与边界 |
| --- | --- |
| 对话历史 | 选取当前分支的可见用户／助手文本，受条数和字符预算限制；不包含 thinking、原始工具结果或其他分支 |
| 项目规则 | 默认关闭；可在 Settings 中按需启用 Pi 已加载的规则（如 AGENTS.md），受预算限制 |
| 目录信息 | 默认目录树关闭；开启后仅在未选入历史时收集。显式 `@目录` 仍可独立收集 cwd 内的有界名称列表，不读取正文 |
| 技能元数据 | 默认关闭；启用后只提供名称和描述，不读取技能正文 |

扩展**不读取源码正文**，普通 `@file` 引用也不会加载文件内容；但先前对话中的代码可能随历史发送。优化模型没有工具，不能自行读文件、联网或执行草稿中的任务。请在使用前确认草稿和启用的背景适合发给所选 Provider；扩展无法保证识别文本中的所有敏感信息。

## 安装

需要 **Node.js 22.19+**、已配置可用模型与认证的 Pi Coding Agent，并在 Pi 的**交互式 TUI** 中使用。

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

无需手动 clone 或执行 `npm ci`。安装后启动 Pi；已有会话执行 `/reload`。

<details>
<summary>仅在当前项目安装，或临时加载</summary>

仅安装到当前项目：

```bash
pi install git:github.com/Steam086/pi-prompt-refine --local
```

仅为一次运行加载，不保存安装配置：

```bash
pi --extension git:github.com/Steam086/pi-prompt-refine
```

</details>

## 第一次使用

### 1. 选择优化模型

在 Pi 中执行：

```text
/refine model
```

首次使用需要选择模型，无需手写配置。优化模型独立于主 Agent，扩展不会自动借用主模型，也不会下载模型。

### 2. 写下草稿，启动优化

在 Pi 主编辑器中输入你的需求，例如：

```text
看看 @src/ 的错误处理，找出可能吞掉异常的地方，先给建议，不要改代码。
```

按 **`Ctrl+\`（Control + 反斜杠，不是 Command）**。工作区为空时会直接启动第一次优化，你可以继续输入。

### 3. 查看结果，决定是否使用

再次按 **`Ctrl+\`** 打开工作台。用 ↑↓ 选中原稿下的模型结果，阅读后：

- 按 **`a`**：将选中结果放入 Pi 主编辑器，**不发送**；你可以继续修改，再自行提交给 Pi。
- 按 **Enter**：进入详情，继续编辑、修订或对比。
- 按 **`q` / Esc**：返回，不接受也不发送；后台任务继续运行。

> **后续新草稿不会自动请求模型。** 工作区已有内容时，`Ctrl+\` 会把新草稿加入 `Unsent`（未提交优化）列表，选中后按 Enter 才启动。草稿未变或已捕获时只定位已有条目，不重复调用；输入框为空时只打开工作台。

不想使用快捷键，也可以直接提交文本：

```text
/refine 看看错误处理，先给建议，不要改代码。
```

然后执行 `/refine` 打开工作台查看结果。带正文的命令会直接发起优化，不只是加入 `Unsent`。

## 常见疑问

**按快捷键没有开始优化？** 先确认已通过 `/refine model` 选择可用模型。已有工作区内容时，新稿只加入 Unsent，需要 Enter 启动。若终端没有传递按键，可用 `/refine 待优化文本`；详见[快捷键排查](docs/shortcut-troubleshooting.md)。不要在普通 Shell 提示符中测试 `Ctrl+\`，它可能触发 SIGQUIT。

**接受结果会覆盖我后来写的内容吗？** 如果接受会覆盖后来修改的 Pi 草稿，扩展会要求确认。可用 `/refine restore` 恢复上次接受前被替换的草稿；该命令只恢复上次接受前的草稿，不支持逐次撤销。

**模型失败了怎么办？** 原稿和已有结果保留。选中原稿或运行记录，按 `m` 重新选模型并启动；扩展不会自动重试或切换 Provider。

**在哪里配置？** 常用选项在 Settings 中。默认模型也可通过 `/refine model` 修改；配置文件为 `<agent-dir>/prompt-refine.json`。快捷键、上下文开关与预算见[配置参考](docs/configuration.md)。

仅支持 TUI 文本。完整按键、发送确认、恢复行为及兼容 `/refine view` 结果页见[使用说明](docs/usage.md)。
