# Pi Prompt Refine

Pi Coding Agent 的后台 Prompt 优化扩展。结合当前草稿与上下文生成候选，由你决定是否接受或发送。

- **不打断输入**：后台生成，不抢焦点，不自动改稿或发送。
- **独立选择模型**：复用 Pi 的 Provider 与认证，不切换主 Agent 模型。
- **结合项目背景**：支持当前分支历史、已加载的项目规则及有界目录信息。
- **保留原始意图**：默认追求最小有效修改，保留约束、授权范围与不确定性。

## 安装

### 环境要求

- Node.js **22.19+**
- 已安装 Pi Coding Agent，并配置可用的 Provider 与认证
- 在 Pi 的交互式 TUI 中使用

### 从 GitHub 安装

无需手动 clone 仓库或执行 `npm ci`：

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

安装后启动 Pi；已有会话可执行 `/reload` 加载扩展。

### 其他加载方式

仅安装到当前项目：

```bash
pi install git:github.com/Steam086/pi-prompt-refine --local
```

仅为一次运行加载，不保存安装配置：

```bash
pi --extension git:github.com/Steam086/pi-prompt-refine
```

## 快速开始

### 1. 选择优化模型

在 Pi 中执行：

```text
/refine model
```

优化模型独立于主 Agent 模型。首次使用需先选择模型，扩展不会自动借用主模型，也不会下载模型。

### 2. 输入草稿并启动优化

在主编辑器中输入草稿，按 **`Ctrl+\`（Control + 反斜杠）**。

优化在后台进行，你可以继续输入。再次按快捷键时：

- **草稿未变**：查看进度或结果，不重复调用。
- **草稿已变**：追加为 `Unsent` 条目并直接选中新原稿，按 Enter 才启动；已有任务保留。
- **草稿已捕获**：定位到对应任务，不重复新增；该任务内已有的选择保留。输入框为空时恢复上次选择。

只有工作区确实为空时，快捷键才自动启动。生成中也可以捕获新稿，不覆盖或取消旧任务。

### 3. 查看并使用候选

宽屏工作台左侧是「原稿 → 各次模型运行」两层树，右侧阅读选中内容；窄屏按 Tab 切换阅读。新任务和新运行在上，旧轮次在下并变灰。原稿父节点显示 original prompt，模型子节点显示结果或进度。

主界面的操作始终针对选中条目，无需先 Apply：

| 按键 | 操作 |
| --- | --- |
| `n` | 新建空白原稿并进入编辑，Enter 只保存 |
| `i` / `e` | 编辑原稿；当前 Unsent 原地修改，已运行或旧轮次原稿另建副本 |
| Enter | Unsent 提交优化；其他条目查看详情 |
| `m` | 选模型，Enter 直接追加运行；不改变默认模型 |
| `x` | 只停止选中的排队／运行子节点 |
| `a` | 将选中结果接受到主编辑器，不发送 |
| `q` / Esc | 返回，不接受或发送 |

## 继续调整

### 用自然语言修订候选

选中结果，Enter 查看详情，再按 `f` 输入调整要求并提交：

```text
再短一点，命令原样保留
```

修订基于当前候选，不改主编辑器、不自动发送；失败时保留原候选。

### 并行任务与不同模型

选中原稿或模型子节点，按 **`m → Enter`** 用另一个模型优化同一原稿。选择器优先提供最近使用和收藏的其他模型，显示本任务的运行状态；可搜索模型。请求沿用该任务的原稿和会话背景，不把某个模型的输出当作新输入，不改变 Settings 中的默认模型。

- 最多同时运行 4 个请求，超出排队；`x` 只停止选中请求。
- 上下选择模型子节点即可快速比较；每份结果记住滚动位置。Enter 详情中按 `c` 对比同任务的另一份结果，宽屏并排显示，窄屏按 Tab 切换；`a` 始终接受明确选中的结果。
- 后台完成不重新排序或抢走选择。耗时加粗，运行中使用强调色；顶部摘要固定，正文独立滚动。完整用量在详情／Usage 中。
- `←` / `→` 切换 **Preview / Usage / Settings**；不再单独保留 History。`/refine history` 是 Usage 的兼容别名。

同一 **round** 的多份 prompt 共享冻结上下文。本轮 prompt 成为 Pi 用户消息后自动归档，旧条目在列表下方暗色显示；下一份新输入才捕获新上下文。归档不取消运行；选中旧原稿按 `i` 可复制到当前 round。旧条目的详情会提示使用较早的会话背景。

记录仅存内存，整个日志最多 100 条；reload / 退出后清除。待处理条目不会被静默淘汰，容量不足时拒绝新增。

### 重新优化或输入新稿

| 按键 | 操作 |
| --- | --- |
| `n` | 新建空白草稿；保存后回列表，Enter 才启动 |
| `i` / `e` | 编辑选中条目的 original prompt |
| `m` | 同一原稿选择模型并运行／重试，保留已有结果 |

结果详情保留 `e` 手工编辑结果、`f` 模型修订、`s` 明确发送。`/refine view` 保留旧结果阅读页及其兼容操作。

### 直接使用命令

不通过主编辑器提交草稿：

```text
/refine 待优化文本
```

查看进度或结果：

```text
/refine view
```

## 上下文与隐私

- 所选 Provider 会收到草稿及已启用的背景信息。
- 默认不读取源码或技能正文，也不会让模型调用工具补读文件。
- 扩展只负责文本改写，不执行草稿中的任务。
- 生成候选不会自动修改主编辑器或发送消息。
