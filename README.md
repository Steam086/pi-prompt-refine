# Pi Prompt Refine

Pi Prompt Refine 是 Pi Coding Agent 的提示词改写扩展。它结合当前对话和项目背景，帮助你把草稿中的需求表达清楚。默认策略要求模型保留原意、约束、授权范围和不确定性，只做必要的修改；已经清楚的草稿可以原样返回。

同一份原稿可以交给多个模型并行优化，再在工作台中比较各自的结果。各模型使用相同的原稿和会话背景，便于对照选择。优化模型独立于主 Agent，复用 Pi 已配置的 Provider 与认证，无需切换主会话模型。

选中候选后，你可以手工编辑，也可以提出「再短一点，命令原样保留」这样的修订要求。满意后接受到主编辑器继续修改，或明确发送给 Pi。生成结果不会自动覆盖输入或发送消息，扩展本身也不执行提示词中的任务。

优化在后台进行，你可以继续输入；关闭面板不会停止请求，完成时也不会抢走焦点。

## 多入口（实验性）

新增 [`/refine-api`](docs/application-api.md)，支持模型配置、草稿保存、显式运行/停止及状态/结果查询，不改变旧 `/refine` 或快捷键。可选 [PI WEB 独立子包](packages/pi-web/README.md) 已有离线契约/构建测试，尚未完成真实宿主与浏览器验收，也未部署。

## 常用工作流

选中模型结果即可操作，按 Enter 查看详情。

| 场景 | 操作 |
| --- | --- |
| 接受 | 按 `a` 写入主编辑器，不发送 |
| 微调 | 详情中按 `e` 手工编辑 |
| 工作区 | 原生居中大浮窗，约 98% 宽／96% 高；各页共享固定外框，背景 session 少量可见，长文内部滚动 |
| 修订 | 列表选中结果或详情按 `f`，默认输入补充要求；Enter 换行，Ctrl+S 请求，Ctrl+E 切换仅编辑／显示来源；未提交要求在本次 Pi 运行期内保留 |
| 复用编辑要求 | Preview 的 Unsent 原稿按 Tab 聚焦内联 Preferences，仅 Space 勾选，Enter 直接开始优化，Esc / Tab 返回并保留选择，`o` 阅读全文；`p`（或 Alt+P）仍打开完整面板，需 Alt+Enter 带回。Revise 中选择并带回后 Ctrl+S 修订。原始任务不变，要求独立传递 |
| 切换模型 | 按 `m` 选模型，Enter 重新优化原稿 |

Preferences 可逐次手动选择，或在 `p` 的列表中按 `g` 明确设为当前目录的项目默认项（`*` 标记）。新原稿自动选中默认项；当前请求可逐项取消或按 `c` 清空，不修改项目默认。切换默认项不改变当前原稿，仍需 Enter／Ctrl+S 显式请求模型；不按关键词推断偏好，旧库自动项仍按手动项处理。

任务要求类 Preferences 是对原任务的**补充，不是替代任务**：输入时与原稿分开传递；协议要求输出时将适用且兼容的回答／行为要求融入完整 prompt 正文，保留原任务、适用的明确约束、条件和授权边界，而非只返回补充要求。仅选择偏好不覆盖原稿明确约束，也不增加执行、工具或委派权限；当前用户明确要求的修改（如翻译 prompt 或缩小任务范围）仍可生效。

Preferences 中，列表／操作栏按 `s` 检查 Selected only，按实际组合顺序显示所有已选快照，再按 `s` 恢复 All 的搜索和浏览位置。新条目保存后回到 Library 并定位，不自动选中；必要时明确提示重置过滤。搜索支持名称／描述／正文的多词 AND 匹配，详见 [Preferences 选择与保存](docs/preference-selection.md)。

Preview 默认只展示当前轮次；全部轮次、Earlier 和恢复记录均可到右侧 Usage 查看。查看中的目标归档后暂时保留，Esc 才返回当前列表，不会被后台结果替换。

结果对比、直接发送及其他操作见[使用说明](docs/usage.md)。

### 多模型比较如何工作

不同模型从**同一原稿和冻结的会话背景**出发，而不是接着改写上一模型的输出。模型选择器支持搜索，优先展示最近使用和收藏的其他模型；一次比较不改变默认模型设置。每个模型会独立记住上次确认使用的 thinking 强度，包括仅用于比较的模型；下次选中后直接按 Enter 即可复用，重启后也保留。

最多同时运行 **4 个请求**，超出后排队。一条请求取消、超时或失败，不影响其他请求；后台完成不改变当前选择或列表顺序。查看、切换或对比已有结果不发起模型调用。

右侧摘要显示耗时、输入／输出 tokens 与单次参考费用，例如 `7s · ↑1.2k ↓300 · ≈$0.012`。缓存拆分、命中率和费用解释在 Usage 详情；未知费用显示 `Cost —`，订阅参考价不代表实际扣费或额度消耗。

## 上下文与数据边界

### 模型会收到什么？

所选优化 Provider 会收到草稿及已启用的背景，**它可能不同于主 Agent 使用的 Provider**。

| 背景来源 | 默认行为与边界 |
| --- | --- |
| 对话历史 | 选取当前分支的可见用户／助手文本，受条数和字符预算限制；不包含 thinking、原始工具结果或其他分支 |
| 项目规则 | 默认关闭；可在 Settings 中按需启用 Pi 已加载的规则（如 AGENTS.md），受预算限制 |
| 目录信息 | 默认目录树关闭；开启后仅在未选入历史时收集。显式 `@目录` 仍可独立收集 cwd 内的有界名称列表，不读取正文 |
| 技能元数据 | 默认关闭；启用后只提供名称和描述，不读取技能正文 |

扩展**不读取源码正文**，普通 `@file` 引用也不会加载文件内容；但先前对话中的代码可能随历史发送。优化模型没有工具，不能自行读文件、联网或执行草稿中的任务。请在使用前确认草稿和启用的背景适合发给所选 Provider；扩展无法保证识别文本中的所有敏感信息。

### 历史保存

默认将原稿、结果、已提交修订要求与运行元数据保存到 session 文件旁的 `.prompt-refine.json` sidecar（最多 100 条 / 2 MiB，权限 `0600`），**不保存完整对话背景、系统模板、项目规则或请求载荷**，不进入主模型上下文。原稿与结果本身仍可能含敏感信息。

`/resume` 或 `/reload` 后通过 `/refine history` 查看。恢复记录可接受、比较及手工编辑；若要再次请求模型，按 `i Copy to current` 复制原稿到当前 round，不会偷偷用新背景续修旧请求。

设 `historyPersistence: false` 并 `/reload` 可停用读写；`/refine history clear` 确认后删除当前 session 的保存历史并暂停保存直到 reload。删除或移动 session 时须同步处理 sidecar。保存范围及恢复限制见[使用说明](docs/usage.md#记录范围与用量)。

## 安装

需要 **Node.js 22.19+**、已配置可用模型与认证的 Pi Coding Agent，并在 Pi 的**交互式 TUI** 中使用。

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

无需手动 clone 或执行 `npm ci`。安装后启动 Pi；已有会话执行 `/reload`。


## 第一次使用

### 1. 选择优化模型

在 Pi 中执行：

```text
/refine model
```

首次使用需要选择模型，无需手写配置。优化模型独立于主 Agent，扩展不会自动借用主模型，也不会下载模型。

### 2. 写下草稿，启动优化

在 Pi 主编辑器中输入你的需求，例如：

```text
看看 @src/ 的错误处理，找出可能吞掉异常的地方，先给建议，不要改代码。
```

按 **`Ctrl+\`（Control + 反斜杠，不是 Command）**，将草稿作为 **Unsent** 保留并打开 Refine。首次和后续输入行为一致：可以先按 `i` 编辑原稿，或按 **Tab → Space → Enter** 在 Preview 选择 Preferences 并直接开始优化（`o` 阅读、`p` 管理库）；启动后自动选中对应的模型运行。

主 Pi 窗口的编辑器上方显示一行 Refine 后台状态：`running` 运行数、`queued` 排队数、`new` 尚未查看的结果数及 `failed` 失败数。运行中只显示当前运行最久的一条的耗时，排队不计入运行时间；无运行且仅有一份新结果时显示其最终耗时，多份新结果不显示耗时。

窄屏先省略耗时和标题，再缩短状态标签；空间仍不足时省略次要计数，优先保留主要状态和打开入口。不轮播，也不展开逐请求列表。打开工作台后清除已完成提醒；正文与用量在工作台内查看。

### 3. 查看结果，决定是否使用

在工作台中查看已选中的模型运行；如果已经关闭工作台，再按 **`Ctrl+\`** 打开。也可用 ↑↓ 选中其他模型结果，阅读后：

- 按 **`a`**：将选中结果放入 Pi 主编辑器，**不发送**；你可以继续修改，再自行提交给 Pi。
- 按 **Enter**：进入详情，继续编辑、修订或对比。
- 按 **`d`**：删除选中请求，按 `y` 确认，Esc / `n` 取消。原稿行删除整组，模型行只删除该次运行；支持 Unsent、已发送及历史请求，运行中的请求会先停止。删除仅影响 Refine 记录，不改动 Pi 编辑器或会话。
- 按 **`q` / Esc**：返回，不接受也不发送；后台任务继续运行。

> **快捷键不会自动请求模型。** 无论工作区是否为空，`Ctrl+\` 都会把新草稿加入 `Unsent`（未提交优化）列表，选中后按 Enter 才启动。草稿未变或已捕获时只定位已有条目，不重复调用；输入框为空时只打开工作台。

不想使用快捷键，也可以直接提交文本：

```text
/refine 看看错误处理，先给建议，不要改代码。
```

然后执行 `/refine` 打开工作台查看结果。带正文的命令会直接发起优化，不只是加入 `Unsent`。

## 常见疑问

**按快捷键没有开始优化？** 先确认已通过 `/refine model` 选择可用模型。首次和后续新稿都只加入 Unsent，需要 Enter 启动。若终端没有传递按键，可用 `/refine 待优化文本`；详见[快捷键排查](docs/shortcut-troubleshooting.md)。不要在普通 Shell 提示符中测试 `Ctrl+\`，它可能触发 SIGQUIT。

**接受结果会覆盖我后来写的内容吗？** 如果接受会覆盖后来修改的 Pi 草稿，扩展会要求确认。可用 `/refine restore` 恢复上次接受前被替换的草稿；该命令只恢复上次接受前的草稿，不支持逐次撤销。

**模型失败了怎么办？** 原稿和已有结果保留。选中原稿或运行记录，按 `m` 重新选模型并启动；从磁盘恢复的记录先按 `i` 复制到当前 round。扩展不会自动重试或切换 Provider。

**在哪里配置？** Settings 的 Context / Optimizer / Advanced 提供上下文开关、历史预算、输出 token 上限、请求超时和原稿长度上限；数值支持常用档位与自定义，返回设置列表后 Ctrl+S 统一保存。默认模型也可通过 `/refine model` 修改；配置文件为 `<agent-dir>/prompt-refine.json`。操作与生效范围见[配置参考](docs/configuration.md)。

仅支持 TUI 文本。完整按键、发送确认、恢复行为及兼容 `/refine view` 结果页见[使用说明](docs/usage.md)。
