# Pi Prompt Refine

Pi Coding Agent 的后台 Prompt 优化扩展。结合当前草稿与上下文生成候选，由你决定是否接受或发送。

- **不打断输入**：后台生成，不抢焦点，不自动改稿或发送。
- **独立选择模型**：复用 Pi 的 Provider 与认证，不切换主 Agent 模型。
- **结合项目背景**：支持当前分支历史、已加载的项目规则及有界目录信息。
- **保留原始意图**：默认追求最小有效修改，保留约束、授权范围与不确定性。

## 安装

### 环境要求

- Node.js **22.19+**
- 已安装 Pi Coding Agent，并配置可用的 Provider 与认证
- 在 Pi 的交互式 TUI 中使用

### 从 GitHub 安装

无需手动 clone 仓库或执行 `npm ci`：

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

安装后启动 Pi；已有会话可执行 `/reload` 加载扩展。

### 其他加载方式

仅安装到当前项目：

```bash
pi install git:github.com/Steam086/pi-prompt-refine --local
```

仅为一次运行加载，不保存安装配置：

```bash
pi --extension git:github.com/Steam086/pi-prompt-refine
```

## 快速开始

### 1. 选择优化模型

在 Pi 中执行：

```text
/refine model
```

优化模型独立于主 Agent 模型。首次使用需先选择模型，扩展不会自动借用主模型，也不会下载模型。

### 2. 输入草稿并启动优化

在主编辑器中输入草稿，按 **`Ctrl+\`（Control + 反斜杠）**。

优化在后台进行，你可以继续输入。再次按快捷键时：

- **草稿未变**：查看进度或结果，不重复调用。
- **草稿已变**：追加为 `Unsent` 条目，保留已有任务；选中后按 Enter 才启动。

只有工作区确实为空时，快捷键才自动启动。生成中也可以捕获新稿，不覆盖或取消旧任务。

### 3. 查看并使用候选

宽屏工作台左侧选择任务／模型，右侧阅读结果；窄屏按 Tab 切换阅读。已完成条目按 **Enter Apply**，将结果应用到 Prompt Refine 主界面，**不会写入 Pi 输入框或发送**。

在应用后的结果页选择操作：

| 按键 | 操作 |
| --- | --- |
| `a` | 接受到主编辑器，不发送 |
| `e` | 手动微调候选 |
| `s` | 明确发送候选 |
| `q` / Esc | 返回，不接受或发送 |

## 继续调整

### 用自然语言修订候选

在面板按 `f`，输入调整要求，再按 Enter：

```text
再短一点，命令原样保留
```

修订基于当前候选，不改主编辑器、不自动发送；失败时保留原候选。

### 并行任务与不同模型

工作台选中一份 prompt，按 `m` 选另一模型，再按 `g` 用**相同冻结输入**追加运行；不必等待上一模型完成。也可以选另一份未发送 prompt，按 Enter 并行启动。

- 最多同时运行 4 个请求，超出排队；`x` 只停止选中请求。
- 切模型、浏览和后台完成都不替换已应用结果；Enter 才 Apply。
- `o` 查看原稿；`i` 编辑独立输入，已有任务时提交只入列。
- `←` / `→` 切换 **Preview / Usage / Settings**；不再单独保留 History。`/refine history` 是 Usage 的兼容别名。

同一 **round** 的多份 prompt 共享冻结上下文。本轮 prompt 成为 Pi 用户消息后自动归档，旧条目暗色显示并归入 Usage；下一份新输入才捕获新上下文，没有手动刷新。归档不取消正在运行的请求；`n` 可把旧原稿复制到当前 round。

记录仅存内存，整个日志最多 100 条；reload / 退出后清除。待处理条目不会被静默淘汰，容量不足时拒绝新增。

### 重新优化或输入新稿

| 按键 | 操作 |
| --- | --- |
| `g` | 使用本次原稿和冻结的上下文、系统模板，追加候选；使用当前模型及 thinking 设置 |
| `r` | 明确优化 Pi 当前草稿，不取消其他任务；共享当前 round 上下文 |
| `i` | 编辑独立输入稿；已有内容时提交只入列，保留输入稿供继续修改 |

### 直接使用命令

不通过主编辑器提交草稿：

```text
/refine 待优化文本
```

查看进度或结果：

```text
/refine view
```

## 上下文与隐私

- 所选 Provider 会收到草稿及已启用的背景信息。
- 默认不读取源码或技能正文，也不会让模型调用工具补读文件。
- 扩展只负责文本改写，不执行草稿中的任务。
- 生成候选不会自动修改主编辑器或发送消息。
