# Pi Prompt Refine

Pi Coding Agent 的后台 Prompt 优化扩展。结合当前草稿与上下文生成候选，由你决定是否接受或发送。

- **不打断输入**：后台生成，不抢焦点，不自动改稿或发送。
- **独立选择模型**：复用 Pi 的 Provider 与认证，不切换主 Agent 模型。
- **结合项目背景**：支持当前分支历史、已加载的项目规则及有界目录信息。
- **保留原始意图**：默认追求最小有效修改，保留约束、授权范围与不确定性。

## 安装

### 环境要求

- Node.js **22.19+**
- 已安装 Pi Coding Agent，并配置可用的 Provider 与认证
- 在 Pi 的交互式 TUI 中使用

### 从 GitHub 安装

无需手动 clone 仓库或执行 `npm ci`：

```bash
pi install git:github.com/Steam086/pi-prompt-refine
```

安装后启动 Pi；已有会话可执行 `/reload` 加载扩展。

### 其他加载方式

仅安装到当前项目：

```bash
pi install git:github.com/Steam086/pi-prompt-refine --local
```

仅为一次运行加载，不保存安装配置：

```bash
pi --extension git:github.com/Steam086/pi-prompt-refine
```

## 快速开始

### 1. 选择优化模型

在 Pi 中执行：

```text
/refine model
```

优化模型独立于主 Agent 模型。首次使用需先选择模型，扩展不会自动借用主模型，也不会下载模型。

### 2. 输入草稿并启动优化

在主编辑器中输入草稿，按 **`Ctrl+\`（Control + 反斜杠）**。

优化在后台进行，你可以继续输入。再次按快捷键时：

- **草稿未变**：查看进度或结果。
- **草稿已变**：优化新的草稿。

### 3. 查看并使用候选

在结果面板中选择操作：

| 按键 | 操作 |
| --- | --- |
| `a` | 接受到主编辑器，不发送 |
| `e` | 手动微调候选 |
| `s` | 明确发送候选 |
| `q` / Esc | 返回，不接受或发送 |

## 继续调整

### 用自然语言修订候选

在面板按 `f`，输入调整要求，再按 Enter：

```text
再短一点，命令原样保留
```

修订基于当前候选，不改主编辑器、不自动发送；失败时保留原候选。

### 比较不同模型（本地试用版）

先生成一次，再按 `m` 选择另一模型、按 `g` 用**相同冻结输入**生成。切模型本身不调用模型，也不丢弃已有结果。

- `c`：循环本任务用过的模型、可用收藏和当前模型。
- `[` / `]`：浏览当前模型的不同候选；修订和手工编辑也保留旧版本。
- `o`：查看原稿。`a` 接受的是眼前选中的候选。
- `←` / `→`：循环切换 Preview / History / Usage / Settings；History / Usage 为只读，也可用 `/refine history`、`/refine usage`。Settings 内按 Tab 切换 Context / Optimizer。

生成或等待发送确认时暂停模型/候选切换；生成中按 `x` 停止后可以继续比较。记录仅保留在内存中，最多 100 条，reload / 退出后清除；暂不提供双栏或差异视图。

### 重新优化或输入新稿

| 按键 | 操作 |
| --- | --- |
| `g` | 使用本次原稿和冻结的上下文、系统模板，追加候选；使用当前模型及 thinking 设置 |
| `r` | 重新优化主编辑器中的当前草稿，重新捕获上下文和模板，开始新任务 |
| `i` | 独立输入新的草稿 |

### 直接使用命令

不通过主编辑器提交草稿：

```text
/refine 待优化文本
```

查看进度或结果：

```text
/refine view
```

## 上下文与隐私

- 所选 Provider 会收到草稿及已启用的背景信息。
- 默认不读取源码或技能正文，也不会让模型调用工具补读文件。
- 扩展只负责文本改写，不执行草稿中的任务。
- 生成候选不会自动修改主编辑器或发送消息。
